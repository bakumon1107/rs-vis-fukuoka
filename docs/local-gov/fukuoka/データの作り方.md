# 福岡県のデータの作り方

`public/data/local-gov/fukuoka-pref/`（共通 JSON 形式の正規化データ）を、県の公開資料から作り直す手順。
形式は [../tasks/20261106_0841_共通JSON形式の設計.md](../tasks/20261106_0841_共通JSON形式の設計.md)、テストの運用は [../knowhow/テストと回帰の運用.md](../knowhow/テストと回帰の運用.md)。

## 1. 入力を置く（リポジトリの外）

以下、入力の置き場所を `$D` と書く（環境変数 `FUKUOKA_DATA` に入れておく。回帰テストもこの変数で場所を受け取る）。

```
$D/
  pdf/<県サイトのファイル名>.pdf   … 説明書・議案・計上額調・決算書類など（URL は index.json の sources と各スクリプトの説明）
  ocr/r8-ippan/p0009.json …       … R8 一般会計の説明書の OCR（PP-OCRv6 ＋ セルの読み直し）
  ocr/r8-ippan-v4/…               … 同じ説明書の旧 OCR（中国語モデル。突き合わせの3つ目の読み取り）
  ocr/r8-toku/…・ocr/r8-toku-v4/… … 特別会計の説明書の同上
```

原本の URL・SHA256・取得日は `scripts/local-gov/fukuoka-pref/sources.json` に書く。書き出しは手元の PDF の SHA256 が一覧と一致することを確かめ、
違えば止まる（県が資料を差し替えたときに気づくため）。資料を取り直したら一覧を更新する。

**置き場所はリポジトリの外の消えない場所（決まりとしてホームの `data/rs-vis-fukuoka/`）。`/tmp` やセッションのスクラッチには置かない**（セッションが替わると消える。
2026-11-13 に消えて取り直した）。原本はコミットしない。

```
$D/
  pdf/      … 原本（sources.json の 21点）
  ocr/      … 上の4つの OCR 結果
  pylib3/   … 新 OCR のパッケージ（pip install --target）: rapidocr 3.10.0・onnxruntime 1.31.1・opencv-python-headless 5.0.0.93・numpy 2.5.4
  pylib/    … 旧 OCR のパッケージ: rapidocr-onnxruntime 1.4.4（ほかは同じ版）
  refill/   … 読み直しのための解釈の結果（中間ファイル）
  work/     … 回帰テストの作業ディレクトリ（--keep。書き出しの入力）
  log/      … OCR・読み直しのログ
  old/      … 流し直す前に退避したページ（日付と理由をディレクトリ名に書く）
```

OCR は時間がかかる（1ページ約10秒。新旧を並べて流して約1.5時間）。手順と設定は [../knowhow/自治体データ調査の手順.md](../knowhow/自治体データ調査の手順.md) の6章。
**OCR の結果は、それを作った時点の `ocr_pages.py` の線の選び方に依存する**。`ocr_pages.py` を変えたら、下の「線の選び方を変えたとき」の手順で
切り方が変わるページを流し直し、回帰テストまで通す（2026-11-13、線の選び方を変えた後に一般会計の OCR を流し直していなかったため、
取り直したら目が1つ消えた。差分の原因はノウハウ「自治体データ調査の手順」6章）。

```bash
D=$FUKUOKA_DATA
O=scripts/local-gov/fukuoka-pref/ocr
# 1) OCR（新旧を並べて流してよい。既にあるページは飛ばすので、止まっても同じコマンドで続きから流せる）
PYLIB=$D/pylib3 OCR_THREADS=5 python3 -P $O/ocr_pages.py $D/pdf/281298.pdf $D/ocr/r8-ippan 9-420
PYLIB=$D/pylib3 OCR_THREADS=5 python3 -P $O/ocr_pages.py $D/pdf/281299.pdf $D/ocr/r8-toku 1-128
OCR_ENGINE=v4ch PYLIB=$D/pylib OCR_THREADS=5 python3 -P $O/ocr_pages.py $D/pdf/281298.pdf $D/ocr/r8-ippan-v4 9-420
OCR_ENGINE=v4ch PYLIB=$D/pylib OCR_THREADS=5 python3 -P $O/ocr_pages.py $D/pdf/281299.pdf $D/ocr/r8-toku-v4 1-128

# 2) 読めなかった数字のセルを読み直す（解釈 → 読み直しを2回。新 OCR は2回目で「読み直すセル: 0」になる）
#    旧 OCR にも当てる（同じエンジンで読み直す）。当てないと旧 OCR の項が予算書と合わず（R8 一般会計 106件中 101件）、
#    突き合わせの3つ目の読み取りとして弱くなる（2026-11-13 に確かめた）
mkdir -p $D/refill
for i in 1 2; do
  python3 -P $O/parse_setsumeisho.py $D/ocr/r8-ippan 9-420 > $D/refill/ippan-$i.json
  PYLIB=$D/pylib3 python3 -P $O/refill_missing.py $D/pdf/281298.pdf $D/ocr/r8-ippan $D/refill/ippan-$i.json
  python3 -P $O/parse_setsumeisho.py $D/ocr/r8-toku 1-128 --tokubetsu > $D/refill/toku-$i.json
  PYLIB=$D/pylib3 python3 -P $O/refill_missing.py $D/pdf/281299.pdf $D/ocr/r8-toku $D/refill/toku-$i.json
  python3 -P $O/parse_setsumeisho.py $D/ocr/r8-ippan-v4 9-420 > $D/refill/ippan-v4-$i.json
  OCR_ENGINE=v4ch PYLIB=$D/pylib python3 -P $O/refill_missing.py $D/pdf/281298.pdf $D/ocr/r8-ippan-v4 $D/refill/ippan-v4-$i.json
  python3 -P $O/parse_setsumeisho.py $D/ocr/r8-toku-v4 1-128 --tokubetsu > $D/refill/toku-v4-$i.json
  OCR_ENGINE=v4ch PYLIB=$D/pylib python3 -P $O/refill_missing.py $D/pdf/281299.pdf $D/ocr/r8-toku-v4 $D/refill/toku-v4-$i.json
done
```

### 線の選び方を変えたとき（`ocr_pages.py` の `choose_vlines` など）

全ページを取り直さず、切り方が変わるページだけを流し直す。

```bash
# 切り方が変わる表を洗い出す（文字は読まないので速い。1ページ約1.5秒）
PYLIB=$D/pylib3 python3 -P $O/check_vlines.py $D/pdf/281298.pdf $D/ocr/r8-ippan 9-420
PYLIB=$D/pylib3 python3 -P $O/check_vlines.py $D/pdf/281299.pdf $D/ocr/r8-toku 1-128
# 出たページを新旧どちらの OCR からも $D/old/<日付>-<理由>/ へ移し、1) を同じコマンドで流し直す（無いページだけ読む）
# 旧 OCR は見出しの読みが違う（簡体字）ので、新旧で表の線が一致するかも確かめる。違うページは旧 OCR だけ移して流し直す
python3 -P $O/check_vlines.py --same-as $D/ocr/r8-ippan $D/ocr/r8-ippan-v4 9-420
python3 -P $O/check_vlines.py --same-as $D/ocr/r8-toku $D/ocr/r8-toku-v4 1-128
# 違うページを旧 OCR だけ移して流し直し、もう一度比べる。流し直しても同じページが残るとき（旧 OCR が見出しを別の語に読む）は、
# 繰り返さずに、そのページの旧 OCR の見出しの文字を見て ocr_pages.py の見出しの語（HEADER_RE・簡体字の寄せ方）を直す
# （直したら、下の「見出しの判定を変えたとき」の全ページの流し直しからやり直す。ocr_pages.py は保存済みのページを読み飛ばすので、
# 流し直さないと4つの OCR 結果は直す前の判定のまま残る）か、
# 新旧で切り方が違うまま残す（多数決の3つ目の読み取りが弱くなるだけで、値は新 OCR と文字層で決まる）。残したページは作業の記録に書く
# そのあと 2) の読み直しと、下の回帰テストを流す
```

### 見出しの判定を変えたとき（`ocr_pages.py` の `HEADER_RE`・`EXPENSE_HEADER_RE`・簡体字の寄せ方・見出しの位置の条件）

`check_vlines.py` は保存済みの見出しの文字で判定するので、見出しの判定の変更は拾えない（見出しと認めなかった表は見出しの文字を保存していない）。
保存された結果から影響するページを絞り込むこともしない。見出しの判定は、表を保存するか・どの線を使うか・続きの表をどう扱うかのすべてに効き、
保存されなかった範囲は手がかりが残らないので、絞り込みの条件を考えるたびに漏れが見つかった（2026-11-14、レビューで3回）。

**4つの OCR 結果（`r8-ippan`・`r8-ippan-v4`・`r8-toku`・`r8-toku-v4`）をすべて `$D/old/<日付>-<理由>/` へ移し、1) を全ページ流し直す**
（新旧の OCR とも同じ判定を使うため。全ページの読み直しは時間がかかるので、見出しの判定の変更はまとめて行う）。
そのあと、上の「線の選び方を変えたとき」の確かめ（`check_vlines.py`・`--same-as`）と 2) の読み直し・回帰テストを流す。
移した古い結果は、流し直した結果と比べる（ページごとの表の数・見出しの有無が変わったページを作業の記録に書く）まで消さない。

## 2. 全ステップを流す（回帰テストを兼ねる）

```bash
FUKUOKA_DATA=$D python3 -P scripts/local-gov/fukuoka-pref/tests/regression.py --keep $D/work
```

抽出・検算・突き合わせ・多数決の出力が `$D/work` に残る。差分が出たら原因を確かめる（テストの運用の決まり）。

## 3. 共通 JSON 形式に書き出す

```bash
python3 -P scripts/local-gov/fukuoka-pref/export_fukuoka_pref.py --work $D/work --pdf-dir $D/pdf \
  --out public/data/local-gov/fukuoka-pref
```

OCR を取り直したときは、先にスクラッチへ書き出して公開中のデータと比べ、変わったのが狙いの箇所だけであることを確かめてから
`public/` へ書き出す（2026-11-13 は、金額の値の違いはなし、名前の値の違いは名前の修正表で直した4件だけ（事項3件・中黒の抜け1件）。
裏付けの数（`agree`）は 206か所で上がり 1か所で下がった（3→2。値は同じ）。裏付けの外れた名前は画像で確かめて修正表に足した）。

`budget-2026-initial.json`（R8 当初予算。一般会計・特別会計14会計）と `index.json`（資料の URL・SHA256）ができる。

名前は書き出しの中で裏付けを取る（`name_evidence.py`。名前の補正の設計 docs/local-gov/tasks/20261106_1241_名前の補正の設計.md）。
- 全文検索の資料は `sources.json` の `"corpus": true` の PDF（`$D/pdf` に置く。SHA256 が違えば止まる）
- 名前の修正表 `ocr/corrections/r8-names.json`（画像で確かめた名前）を当てる。当たる先がない・1件に絞れない修正があれば止まる
- 裏付けのない款・項・目・節の一覧が `$D/work/names-unresolved.json` に出る（ページ・位置付き）。
  残っていれば、ページ画像の切り抜きで確かめて名前の修正表に足す。要約の「名前の出典」で出典ごとの件数を見る
