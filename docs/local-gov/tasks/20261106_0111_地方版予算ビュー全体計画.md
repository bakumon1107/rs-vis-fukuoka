# 地方版予算ビュー 全体計画

作成: 2026-11-06
状態: たたき台（フェーズ1の調査結果を見て更新する）

## ゴール

1. 福岡県の予算をサンキー図などで可視化した「福岡県予算ビュー」を公開する。
2. その成果を、他の自治体にもデータと設定の追加だけで展開できる形に整える。

## フェーズ

### フェーズ0: リポジトリ運用の準備

- [x] `upstream` リモート追加（ローカル）
- [x] `local-main` 作成・push
- [ ] GitHub の既定ブランチを `local-main` に変更（ユーザーが実施）
- [ ] ルールセット: `main`（削除・force push・直接 push 禁止。管理者のみ例外）、`local-main`（削除・force push 禁止、PR 必須）
- [x] `docs/local-gov/` 作成
- [ ] CLAUDE.md に地方版の運用（文書の置き場所・ブランチ）を追記

### フェーズ1: 福岡県データの調査（`docs/local-gov/fukuoka/`）

- 公開されている予算データの所在と形式（当初予算書・予算説明書・事業別資料・決算書、PDF/Excel/CSV、オープンデータカタログ）
- 階層構造（会計 → 款 → 項 → 目 → 事業 …）と、国の RS システム（事業 → 支出先）との対応
- 支出先データ（委託・補助の相手先）がどこまで取れるか
- 年度・金額単位（千円単位が多い想定。アプリ内部は1円単位）
- 利用条件（ライセンス）

成果物: データ調査メモと、可視化できる範囲の判断。

### フェーズ2: 本家コードの棚卸し

- 国の予算固有の前提（所管・RS 事業 ID・総額・文言・URL など）がどこにハードコードされているか
- 地方版で使う画面と使わない画面（`/budget-sankey` を中心に、`/fiscal-space` `/tax-burden` などの扱い）
- データパイプライン（`scripts/`）と型（`types/`）の差し替え口

成果物: 改修方針（どこを設定化し、どこを福岡用に足すか）。

### フェーズ3: 福岡県版 MVP

- 福岡県データのパイプライン（CSV/Excel → JSON）
- 自治体設定（名称・年度・データパス・表示文言）の最小限の仕組み
- サンキー図（会計 → 款 → 項 → 目 →（事業））
- トップページ・メタ情報（OGP）の福岡版
- デプロイ（`local-main` をデプロイし、設定で福岡を選択）

### フェーズ4: 汎用化

- 2つ目の自治体を試しに入れ、差分から共通化の範囲を決める
- 自治体追加手順書の作成

## 未決事項

- 公開時の名称・ドメイン
- デプロイ先（Vercel 個人アカウント等）。本家の Vercel / Supabase / Terraform 設定は地方版では使わない想定
- 事業コメント機能（Supabase / AI）を地方版でも使うか
