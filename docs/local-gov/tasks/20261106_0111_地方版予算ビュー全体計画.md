# 地方版予算ビュー 全体計画（大枠）

作成: 2026-11-06
状態: 大枠の計画（合意待ち）。OCR 方式の検証などの個別作業は、この計画に合意してから着手する。
関連: [福岡県予算ビュー計画書（データ棚卸し）](20261106_0122_福岡県予算ビュー計画書.md)

## 1. ゴール

1. 福岡県の予算を可視化する「福岡県予算ビュー」を公開する（1件目の事例）。
2. その成果を、他の自治体にもデータと設定の追加だけで展開できる形にする。
3. フォーク元（国の予算版 `team-mirai-volunteer/rs-vis`）の改善を取り込み続けられるよう、差分を管理しやすく保つ。

## 2. 前提と制約

### 2.1 フォーク元との関係

- フォーク元は**国の予算**の可視化として作られている。データ・用語・画面・文言の多くが国の予算を前提にしている（3章）。
- フォーク元は今後も開発が続く。`main` をミラーとして追従し、`main → local-main` の PR で取り込む。
- 取り込みのたびに衝突しないよう、**フォーク元のファイルへの変更は「差し替え口」を作る最小限にとどめ、地方版の実装は新しいディレクトリに置く**（5章）。

### 2.2 フォーク運営のルール（AGPL-3.0 とチームみらいのガイドライン）

ライセンスは AGPL-3.0。チームみらいの別リポジトリ（みらい議会）の
[FORK_GUIDELINES.md](https://github.com/team-mirai/mirai-gikai/blob/develop/FORK_GUIDELINES.md) に合わせる。
このリポジトリ自体にはガイドラインがないが、同じ団体の方針として準拠する。

| 項目 | 要件 | このリポジトリで対応する場所（現状） |
|---|---|---|
| サービス名称 | 独自の名称にする（本家の名称を使うなら「○○＠地域名」形式） | `app/lib/product.ts`（`PRODUCT_NAME = '政府予算ビュー'`、`PRODUCT_ATTRIBUTION = 'チームみらい 政府予算ビュー'`）、`app/lib/page-metadata.ts` |
| ロゴ | チームみらいのロゴを使わない | `public/logos/team-mirai-wordmark.svg`、`components/navigation/AppHeader.tsx` |
| アイコン | favicon・アプリアイコンを差し替える | `app/favicon.ico`、`app/icon.png`、`app/icon.svg`、`app/apple-icon.png` |
| OGP 画像 | 差し替える | `public/og/*.png`（17枚） |
| カラーテーマ | primary カラーを使わない | `app/globals.css`（`--primary: #2aa693` チームみらいティール、`--primary-accent`、`--ring`、`--mirai-*` 系、`--mirai-surface-teal` など）、`app/layout.tsx` の `themeColor` |
| 免責文言 | 「これは政党チームみらいが運営しているものではありません」を分かりやすい場所に表示 | フッター・`components/legal/` |
| ソースコードへのリンク | フォーク版**自身**の公開リポジトリへリンクする（AGPL 第13条） | `components/legal/LegalLinks.tsx`、`app/terms/page.tsx`、`components/lp/FigureBasis.tsx`（いずれも `team-mirai-volunteer/rs-vis` を直書き） |
| 運営者表記 | 利用規約・プライバシーポリシーの運営主体を自分たちに変える | `app/terms/page.tsx`、`app/privacy/page.tsx`、`components/legal/LegalDocument.tsx` |
| 変更の明示 | 改変した旨と日付を明記（AGPL 第5条(a)） | README・フッター |
| 推奨: 本家へのリンク | フォーク元へのリンクを置く | フッター |

「チームみらい」「team-mir」を含むファイルは `app` `client` `components` 配下に約25件ある（棚卸しの対象）。

**方針**: 名称・運営者・色・ロゴ・リポジトリ URL・免責文言を**1か所のサイト設定（ブランド設定）に集め**、各所はそこを参照する形にする。
フォーク元の `product.ts` はすでにこの考え方（製品名の直書き禁止）なので、それを広げる。

## 3. 国の予算ならではの部分（地方版で扱いが変わるもの）

### 3.1 データとドメイン

| 国版の概念 | 主な実装 | 地方版（福岡県）での扱い |
|---|---|---|
| RS システム（行政事業レビュー）: 事業 ID・事業 → 支出先・再委託 | `scripts/`（RS CSV の取得・抽出）、`app/lib/subcontracts/`、`recipient-*`、`vendors` | 事業と支出先を結ぶデータはない。福岡県では建設工事の入札結果（Excel）と特命随意契約（PDF）で**部局・課の単位の契約先**は取れる → サンキー図の列にはせず、別の「契約先」ビューの候補（MVP の範囲外）。再委託の層は持たない |
| 所管（府省庁）による分類 | `ministry` 列、府省庁フィルタ | 県の予算書の骨組み（款）は目的別で、**部局とは一致しない**。部局での絞り込みには、事項に課名を付ける照合が必要（施策別資料・見直し一覧・行政評価から） |
| 財務省の予算書（所管 → 組織 → 項 → 目）: `mof-*` | `app/lib/mof-*.ts`、`public/data/mof-budget-*.json.gz` | 県の予算に関する説明書（会計 → 款 → 項 → 目 → 説明欄の事業）に置き換え |
| 統合サンキー図の列 | `types/unified-budget.ts` の `UnifiedColumn`（revenue / account / ministry / organization / section / koumoku / program / program-spending / recipient） | 列の構成が違う（財源・歳入 / 会計 / 款 / 項 / 目 / 事項）。**2026-11-07 改め**: 国の列定義は差し替えず、地方版の描画部品
（`LocalSankeyChart`）を別に作って国版の配置計算・帯の形だけを使う。列の組み合わせは見方ごとに `app/lib/local-gov/graph.ts` が決める
（[画面とグラフの設計](20261106_1327_地方版サンキー図の画面とグラフの設計.md) 4.2） |
| 府省庁名の正規化 | `app/lib/unified-budget/ministry-names.ts` | 不要（部局名は行政評価との照合で使う） |
| 予算年度と執行年度のずれ（RS の「予算年度2023実績」等） | `app/lib/rs-fiscal-year.ts` | 県は当初予算の年度で扱う |
| 単位: 1円単位、総額 151兆円 | `CLAUDE.md`・各所の定数 | 1円単位は踏襲（県の資料は千円単位なので取り込み時に換算）。総額はデータから求める（画面がグラフを組み立てて合計する。設定に書くと二重管理になる。2026-11-07 改め） |
| 政策評価・品質スコア | `/quality`、`policy-evaluation.ts` | **県の行政評価（事務事業評価）**で置き換えられる可能性がある |

## 4. 地方版の構成（設計の考え方）

### 4.1 選択肢

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 既存の画面に分岐を入れる | `/budget-sankey` などの中で「国 or 自治体」を分岐 | 画面を作り直さずに済む | フォーク元のファイルを広く書き換えることになり、取り込みのたびに衝突する |
| **B. 地方版の画面を新しく作り、部品を再利用する** | 地方版のページ・ドメインロジック・データを新しいディレクトリに置き、サンキー図の描画やフィルタなどの汎用部品だけ再利用する | フォーク元との衝突が少ない。国の前提に縛られない | 汎用部品が国の型に依存している箇所は差し替え口が必要 |
| C. 新しいリポジトリで作り直す | 必要な部品だけ持っていく | 一番すっきりする | フォーク元の改善を取り込めなくなる |

**推奨は B。** 国版の画面はコードとして残したまま、地方版の公開時は**設定（デプロイの環境変数）で国版の画面を出さない**ようにする。

### 4.2 ディレクトリ構成（案）

```
config/local-gov/      … 2026-11-07 時点では未作成（ブランドの差し替えは5章の決めごとが済んでから作る）
  site.ts              … ブランド設定（名称・運営者・色・ロゴ・リポジトリURL・免責文言）。未作成
  governments/
    fukuoka-pref.ts    … 自治体設定（名称・データパスなど。2026-11-07 時点では未作成: 会計・年度・出典は index.json と正規化データに、
                         サンキー図の列は graph.ts の見方に持たせている）
app/local/[gov]/       … 2026-11-06 決定（7章。当初は app/local/ または app/(local)/ の案）
  ...                  … 地方版のページ（トップ・サンキー図・事業詳細など）
app/lib/local-gov/     … 地方版のドメインロジック（県の予算書 → サンキーグラフ、行政評価との照合）
types/local-gov.ts     … 地方版の型（会計・款・項・目・事業・財源・節）
scripts/local-gov/
  fukuoka-pref/        … 福岡県のデータパイプライン（取得・抽出・検算・JSON 生成）
public/data/local-gov/
  fukuoka-pref/        … 生成データ（圧縮せず JSON のまま Git 管理。小さいので差分をレビューできる。大きくなったら国版と同じ .gz にする）
docs/local-gov/        … 地方版の文書（このフォルダ）
```

- 自治体 ID はローマ字の slug（例: `fukuoka-pref`、将来 `fukuoka-city` など）。都道府県と市町村を区別できる形にする。
- 地方版の公開時は、環境変数（例: `NEXT_PUBLIC_SITE_EDITION=local`、`LOCAL_GOV_ID=fukuoka-pref`）で
  - トップページ・ナビゲーション・サイトマップを地方版に切り替える
  - 国版のページは出さない（ナビから外す＋アクセスされたら 404 またはトップへ）
- フォーク元のファイルで手を入れるのは、主に**差し替え口**だけにする:
  - ブランド（`product.ts`・`layout.tsx`・`globals.css`・`AppHeader`・`legal/`）を設定参照に変える
  - ナビゲーション・サイトマップのページ一覧を設定から読む
  - サンキー図: 国の列定義（`UnifiedColumn`）に依存する描画部品は変えず、地方版の描画部品を別に作る（2026-11-07 改め。上の 3.1 の表）

### 4.3 フォーク元の更新を取り込むときの考え方

- 国版の画面・データ・スクリプトの更新は、地方版に影響しないので基本的にそのまま取り込む。
- 衝突が起きやすいのは差し替え口を入れたファイル（ブランド・ナビ・共通部品）。ここは変更を小さく保ち、取り込み時に確認する。
- 汎用部品の改善（描画の高速化・UI の改善）は自動的に地方版にも効く。

### 4.4 自治体の汎用化の範囲

- 1件目（福岡県）は具体的に作る。ただし最初から、**自治体固有のものは自治体設定と `scripts/local-gov/<自治体>/` に閉じ込める**。
  （2026-11-07 補足・例外: 「データについて」の数字の作り方・検算の方法の説明文は、MVP では福岡県の資料に合わせて画面に書く。
  2件目の自治体のときに `index.json` に移す。[画面とグラフの設計](20261106_1327_地方版サンキー図の画面とグラフの設計.md) 4.2）
- 予算書の様式は自治体ごとに違う（款の構成は地方自治法の様式で共通部分が多いが、説明書の体裁はばらばら）。
  → **データパイプラインは自治体ごと、生成する JSON の形は共通**にする。共通の JSON 形式を決めることが汎用化の要。
- 2件目に着手するときに、共通 JSON 形式と自治体設定の項目を見直す。
