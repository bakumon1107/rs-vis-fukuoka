# サイト全体から国版を外す設計（福岡県版）

- 作成: 2026-11-27
- 状態: 設計（実装前。確認待ち）
- 関連: [地方版予算ビュー全体計画](20261106_0111_地方版予算ビュー全体計画.md) 3.2・3.3・4.2（「設定で国版の画面を出さない」）、[公開前のサンキー図の足しと公営企業会計の設計](20261121_0100_公開前のサンキー図の足しと公営企業会計の設計.md)

## 1. 目的

このフォークのサイトを「福岡県の予算ビュー」にする。国版（本家の「政府予算ビュー」）のページ・リンク・ブランド・AI 機能を、訪問者から見えないようにする。

- トップ `/` を福岡県の入口にする
- 共通ヘッダーから「政府予算ビュー」の名前と国版のナビ（サンキー図・バブル図・評価一覧・委託構造・事業者・基金）と AI ボタンを外す
- 国版のページ・API を URL で直接開いても出ないようにする
- 本家（`main`）を `local-main` へ取り込むときの衝突を最小にする

全体計画 4.2 では「ブランド（`product.ts`・`layout.tsx`・`globals.css`・`AppHeader`・`legal/`）とナビ・サイトマップを設定参照に変える」としていた。本書はこれを絞り込み、**本家のファイルは `app/layout.tsx` の 1 つだけを変える**形を推奨する（4章）。

- AI ナビ（ヘッダーの AI ボタン）は環境変数がなくても BYOK で動く。サイト提供 AI は `SANKEY_AI_CHAT_ENABLED=1` とキーが必要。

### 2.7 地方版から国版へのリンク

地方版の画面（`app/local/[gov]/*`・`client/components/local-gov/*`）のリンク先は `/local/${gov}`・`/local/${gov}/funds`・`/local/${gov}/about` と外部の出典だけで、国版のページへの直接リンクはない。国版へ行く経路はヘッダー（ブランド・ナビ・メニュー）と AI ナビだけ。

### 2.8 CI

`.github/workflows/checks.yml` はすべての PR で typecheck・lint・`npm test`・build・`test:e2e`（国版の画面を前提とする Playwright テスト）を回す。国版を**コードごと消すと e2e が通らなくなる**。

## 3. 方針の案

### 案1（推奨）: 版の切り替え（環境変数）＋ 新規の middleware ＋ 地方版専用の外枠

- 環境変数 `NEXT_PUBLIC_SITE_EDITION=local`（と `NEXT_PUBLIC_LOCAL_GOV_ID=fukuoka-pref`）を立てたデプロイだけを福岡県版にする。未設定なら今のまま国版（本家と同じ）。
- 新規の `middleware.ts`（本家に存在しない）で、福岡県版のときだけ**許可リスト方式**で URL を絞る:
  - 許可: `/local/**`、`/data/local-gov/**`、`/_next/**`、アイコン類（`/favicon.ico`・`/icon.png`・`/icon.svg`・`/apple-icon.png`）、地方版の OGP 画像、`/terms`・`/privacy`・`/robots.txt`・`/sitemap.xml`（地方版のものへ書き換え）
  - `/` → `/local/fukuoka-pref` へ（リダイレクトか書き換え。6章で決める）
  - それ以外のページ → `/` へリダイレクト（または 404）。`/api/**` → 404。国の静的データ（`/data/*.json.gz` 等）・国版 OGP → 404
  - 許可リストなので、**本家が新しいページや API を足しても自動で隠れる**（取り込みのたびにリストを直さなくてよい）
- 本家のファイルで変えるのは `app/layout.tsx` だけ。福岡県版のときは
  - `AppHeaderProvider`（国版ヘッダー・AI ナビ）の代わりに地方版のヘッダー（新規）で包む
  - 既定のメタデータを地方版のもの（新規の設定から作る）にする
  - GA は `NEXT_PUBLIC_GA_MEASUREMENT_ID` が明示されたときだけ読み込む（本家のプロパティへ送らない）
- 利用規約・プライバシー・サイトマップ・robots は地方版用を**新しいパス**（例: `app/local-site/terms/page.tsx`、`app/local-site/sitemap.xml/route.ts`）に作り、middleware で `/terms` などから書き換える。本家の `app/terms`・`app/sitemap.ts` 等は触らない。

| 観点 | 評価 |
|---|---|
| 本家との衝突 | **ほぼない**。本家ファイルの変更は `app/layout.tsx` の数行（本家の変更は 2026-09 以降 6 回）。他は新規ファイルか地方版のファイル。`middleware.ts` は本家にないが、本家が将来作ったら add/add の衝突になる（そのときは中身を合わせる） |
| 作業量 | 中〜小（middleware・判定の関数とテスト・ヘッダー・フッター・規約 2 本・サイトマップ・メタデータ） |
| 戻しやすさ | 高い。環境変数を外せば国版に戻る。コードを外すのも新規ファイルの削除と `layout.tsx` の数行だけ |
| CI | 環境変数未設定の CI は国版のままなので、本家の e2e はそのまま通る |
| 欠点 | 国版のコード・データはビルドに残る（ビルド時間・関数サイズは今と同じ）。開発中は `.env.local` に版を書かないと地方版の見た目にならない |

### 案2: 本家の共通ファイルを地方版の内容に直接書き換える（切り替えなし）

`pages.ts` を地方版の 3 ページに、`product.ts` を「福岡県予算ビュー」に、`app/page.tsx` を福岡県のトップに、`AppHeader.tsx` から AI ボタンを外し、`page-metadata.ts`・`sitemap.ts`・`terms`・`privacy`・`LegalLinks.tsx` を書き換える。国版のページは middleware で隠す。

| 観点 | 評価 |
|---|---|
| 本家との衝突 | **多い**。`pages.ts`（28 回）・`AppHeader.tsx`（19 回）・`app/page.tsx`（12 回）など、本家がよく変えるファイルばかり。国版のページを足すたびに `pages.ts` が衝突する |
| 作業量 | 中（書き換える量は案1と同程度だが、国版との型の整合（`NavPageHref` を使う国版ページが多数）の直しが出る） |
| 戻しやすさ | 低い。国版の表示を見るには差分を戻す必要がある |
| CI | 国版の e2e（トップ・ナビ・タイトル）が落ちるので、e2e を地方版用に直すか止める必要がある |

### 案3: 国版のページ・API・データ・スクリプトを削除する

| 観点 | 評価 |
|---|---|
| 本家との衝突 | **非常に多い**。本家が国版のファイルを変えるたびに「こちらは削除・本家は変更」の衝突になる（数百ファイル） |
| 作業量 | 大（削除の連鎖で共通部品の型エラー・テスト削除が広がる） |
| 戻しやすさ | 低い |
| 利点 | ビルドが軽くなる（国のデータ 100MB 超の展開と関数同梱がなくなる） |

### 推奨: 案1

全体計画 4.1 案 B・4.2 の「設定で国版の画面を出さない」をそのまま実現し、本家ファイルの変更を `app/layout.tsx` 1 つに抑えられる。全体計画 4.2 では `product.ts`・`AppHeader`・`legal/`・ナビ・サイトマップにも差し替え口を入れる想定だったが、地方版の外枠を別に作って middleware で振り分ければ要らない。ビルドを軽くしたい場合は、後で `scripts/decompress-data.sh` に版の判定を足す（本家ファイルの変更が 1 つ増える）ことを別途検討する。

## 4. 設計（案1）

### 4.1 版の判定（純粋関数）

新規 `app/lib/local-gov/site-edition.ts`:

- `siteEdition()`: `NEXT_PUBLIC_SITE_EDITION === 'local'` なら `'local'`、それ以外は `'national'`
- `localGovId()`: `NEXT_PUBLIC_LOCAL_GOV_ID`（未設定なら `fukuoka-pref`）
- `routeForLocalEdition(pathname)`: パスを受けて `{ kind: 'pass' } | { kind: 'rewrite', to } | { kind: 'redirect', to } | { kind: 'notFound' }` を返す。許可リストと書き換え表はここに置く（middleware はこれを呼ぶだけ）

`NEXT_PUBLIC_` にするのは、ヘッダー（クライアント部品）でも同じ値を使うため。値はビルド時に埋め込まれるので、版を変えたら再ビルドが要る。

### 4.2 middleware

新規 `middleware.ts`（リポジトリ直下）:

- 版が `national` なら何もしない（`NextResponse.next()`）
- `local` なら `routeForLocalEdition` の結果に従う
- `matcher` は静的ファイルも含める（国の `/data/*.json.gz`・`/og/*.png` を止めるため）。`/_next/static` 等は早めに通す

書き換え表（案）:

| 来たパス | 福岡県版での扱い |
|---|---|
| `/` | `/local/fukuoka-pref` へ（6章で リダイレクト/書き換え/専用トップ を決める） |
| `/local/**` | そのまま |
| `/data/local-gov/**` | そのまま |
| `/terms`・`/privacy` | `/local-site/terms`・`/local-site/privacy` に書き換え（URL は変えない） |
| `/sitemap.xml`・`/robots.txt` | `/local-site/sitemap.xml`・`/local-site/robots.txt` に書き換え |
| `/og/local/**`・アイコン類 | そのまま |
| `/api/**` | 404 |
| その他のページ（国版） | `/` へリダイレクト（または 404。6章） |
| その他の静的ファイル（国のデータ・国版 OGP・`/lp/*` の画像など） | 404 |

`/local-site/**` を直接開いた場合も書き換え先として通す（害はない）。国版の版では `/local-site/**` は普通のページとして開けてしまうが、本家には存在しないパスなので問題にしない。

### 4.3 ヘッダー（地方版の外枠）

新規 `client/components/local-gov/LocalSiteHeader.tsx`（国版の浮島ヘッダーと同じ見た目・高さ 72px。`AppHeader` の部品は import せずに作る。国版のヘッダーが変わっても影響を受けないため）:

- 左: ブランド（アイコン＋地方版の製品名。`/` へ）
- 中央: 主要ナビ — 「サンキー図」（`/local/fukuoka-pref`）・「基金」（`/local/fukuoka-pref/funds`）・「データについて」（`/local/fukuoka-pref/about`）
- 右: メニュー（同じ 3 つ＋利用規約・プライバシー・ソースコード）。**AI ボタンは置かない**
- 現在地の判定は `usePathname()` で行う

`app/layout.tsx` の変更（福岡県版のときだけ）:

```tsx
// 方針のイメージ（実装時に確定）
{siteEdition() === 'local'
  ? <><LocalSiteHeader />{children}</>
  : <AppHeaderProvider>{children}</AppHeaderProvider>}
```

地方版の 3 画面にある `<AppHeader current="/" />` は、プロバイダがないときに 72px の余白だけを出す本家の挙動に頼ることになる。本家がこの挙動を変えても壊れないよう、地方版のファイル側で新規の `LocalHeaderSpacer`（72px の余白）に置き換える（地方版のファイルなので衝突しない）。国版の版で `/local/...` を開いたときも、国版ヘッダーの下に余白ができるので表示は崩れない。

### 4.4 フッター

新規 `client/components/local-gov/LocalSiteFooter.tsx` を地方版の 3 画面（またはトップ）に置く:

- 製品名と運営者（6章で決める）
- 「本サイトは、チームみらいの『政府予算ビュー』（AGPL-3.0）をもとに〇〇が作成した非公式の地方版です。チームみらいとは関係ありません」などの表記（文言は6章）
- データの出典（福岡県の予算書・決算書等）と免責
- 利用規約・プライバシーポリシー・連絡先（**本家のアドレスは使わない**）
- **ソースコード（このフォークのリポジトリ、AGPL-3.0）**へのリンク。AGPL-3.0 はネットワーク越しに使わせる改変版の利用者にソースを提供することを求めるので、本家ではなくこのフォークを指す必要がある

### 4.5 トップページ

最初の公開では `/` を `/local/fukuoka-pref`（サンキー図）に向ける。全体計画のとおり複数の自治体を出すことになったら、`/` を自治体の一覧にする（`/local-site/home` を新規に作り middleware で書き換え）。専用のトップ（ヒーロー＋「サンキー図」「基金」「データについて」のカード）を最初から作るかは6章で決める。

### 4.6 メタデータ・OGP・サイトマップ・robots

- 新規 `app/lib/local-gov/site.ts`: 地方版のブランド設定（製品名・運営者・説明文・リポジトリ URL・連絡先・免責の文）。全体計画 4.2 の `config/local-gov/site.ts` に当たるもの。レイヤー規則（ドメインは `app/lib/`）に合わせてここに置く

## 6. 決めてほしいこと

1. **方針**: 案1（版の切り替え＋middleware＋地方版の外枠）でよいか
2. **製品名**: 案「福岡県予算ビュー」「ふくおか予算ビュー」「福岡県の予算ビュー」「地方予算ビュー 福岡県」。複数の自治体を出す将来を見るなら、自治体名を外したサイト名（例「地方予算ビュー」）＋画面に自治体名、という形もある
3. **運営者の表記**: 個人名・ハンドル名・団体名のどれを出すか。連絡先（メール・GitHub の Issue など）
4. **本家との関係の表記**: 「チームみらいの政府予算ビュー（AGPL-3.0）をもとにした非公式の地方版」と明記し、チームみらいとは関係がないことを書くか（推奨: 書く。見た目が本家と同じデザインなので、本家の公式と誤解されないように）。本家のデザイン（色・浮島ヘッダー）をそのまま使ってよいか
5. **トップ `/` の形**: (a) `/local/fukuoka-pref` へリダイレクト（最小・推奨） (b) URL を `/` のまま書き換えで表示 (c) 専用のトップ（ヒーロー＋カード）を作る
6. **国版の URL を開かれたとき**: ページは (a) `/` へリダイレクト（推奨） (b) 404。API は 404 で固定でよいか
7. **ナビの項目**: 「サンキー図」「基金」「データについて」の 3 つでよいか（バブル図は止めているので出さない）
8. **検索エンジン**: `noindex` を公開と同時に外すか、数字の確認が済むまで残すか
9. **計測**: GA を使うか（使うならフォーク用の測定 ID を用意）。使わないならプライバシーポリシーの記載も減る
10. **デプロイ先と URL**: Vercel の個人アカウント等・独自ドメインの有無（全体計画 7章の未決事項）。ここが決まらないと `SITE_URL`・OGP・サイトマップの絶対 URL が決まらない
11. **利用規約・プライバシーポリシーの中身**: 誰が書くか（下書きは用意できる）。AI・投稿機能がないので短くできる
12. **国のデータのビルド**: 国のデータの展開と関数同梱はそのまま残してよいか（残す＝衝突なし。外す＝ビルドが軽くなるが本家ファイルの変更が増える）

## 7. 検証方法

実装後に次を行う（dev サーバー・ビルドを動かす前に、動いている dev サーバーを止める。メモリ 11GB のため並行で動かさない）。

1. `npm run lint`・`npm run typecheck`・`npm test`（新規の `tests/local-gov-site-edition.test.ts` を含む）
2. 国版のままの確認（環境変数なし）: `npm run build` が通り、`/`・`/budget-sankey` が今と同じであること（`npm run test:e2e` の主要なもの。CI でも回る）
3. 福岡県版の確認（`.env.local` に `NEXT_PUBLIC_SITE_EDITION=local` を書いて `npm run build && npm start`）:
   - 画面: `/` → 福岡県のサンキー図に行く。ヘッダーに「政府予算ビュー」・国版ナビ・AI ボタンが出ない。ナビの 3 項目とメニューが動く。フッターの非公式表記・ソースコード（このフォーク）・規約リンク。スマホ幅（375px）でヘッダーが崩れない
   - リダイレクト・404（`curl -sI` で状態コードと `Location` を見る）: `/budget-sankey`・`/sankey-svg`・`/quality`・`/funds`・`/mof-kou/1`・`/lp` → `/` へ。`/api/funds`・`/api/mcp`・`/api/ai/sankey-chat` → 404。`/data/funds.json.gz`・`/og/home.png` → 404。`/data/local-gov/fukuoka-pref/index.json` → 200
   - `/terms`・`/privacy` が地方版の中身。`/sitemap.xml` に地方版の URL だけ。`/robots.txt` の中身
   - メタデータ: `/`・`/local/fukuoka-pref`・`/funds`・`/about` の `<title>`・`og:title`・`og:site_name`・`og:image` に「政府予算ビュー」「チームみらい」が出ないこと
   - GA: ID 未設定のとき gtag のスクリプトが出ないこと
4. 本家の取り込みの試し: `main` を作業ブランチに試しにマージし、衝突が `app/layout.tsx` 以外に出ないことを確かめる（試しなので結果は捨てる）

## 8. リスクと注意

- **GA の既定値**: 何もしないとフォークの本番の計測が本家の GA プロパティに送られる。`app/layout.tsx` の変更で福岡県版では明示した ID のときだけ読み込むようにする
- **AGPL-3.0**: ソースコードのリンクを本家のままにすると、改変版のソース提供の義務を満たせない。フッターのリンクはこのフォークにする
- **本家の連絡先・運営者名**: 利用規約・プライバシー・フッターに本家（チームみらい）の名前と連絡先が出たままだと、本家の公式サイトに見える。地方版の規約で置き換える
- **OGP の継承**: 地方版の layout が title しか上書きしていないため、今のまま共有すると国版の説明と画像が出る
- **middleware の取り込み**: 本家が将来 `middleware.ts` を作ると add/add の衝突になる。判定は `site-edition.ts` に寄せておき、`middleware.ts` は数行に保つ
- **本家ヘッダーへの依存**: 地方版の画面が本家の `AppHeader`（プロバイダなしで余白だけ出す挙動）に頼っている。4.3 のとおり `LocalHeaderSpacer` に置き換えて切り離す
- **版の判定はビルド時**: `NEXT_PUBLIC_` の値はビルドに埋め込まれる。プレビューと本番で版を変えるなら、それぞれのデプロイで設定する
- **CI**: CI は版を設定しないので、福岡県版の振る舞いは単体テスト（振り分け表）でしか自動で確かめられない。e2e を足すなら、版を設定したジョブを別に作るかどうかを決める（本家の `checks.yml` を変えると衝突しうるので、足すなら新規のワークフローファイルにする）
