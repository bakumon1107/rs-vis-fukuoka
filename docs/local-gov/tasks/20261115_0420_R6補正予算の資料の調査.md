## 2. 取り込むときの見込み

- OCR: 新・旧の2つで 1ページ約10秒 × 832ページ ≒ 約2.5時間（[補正予算の取り込み設計](20261106_0834_補正予算の取り込み設計.md) の見積もりどおり）。
  名前は NDLOCR-Lite（約3秒/ページ。約40分）を足す
- **減額の印 △**: OCR は △ を読まない（R8 9月第3号で確かめた。ノウハウ「自治体データ調査の手順」）。R8 は文字層の △ を使ったが、R6 は文字層がない。
  代わりの手がかり: (1) 目の検算（補正前 + 補正額 = 計）で符号が決まる（補正額の絶対値と 計 − 補正前 が一致すれば、その差の符号）、
  (2) 節・財源内訳・説明欄の合計が補正額と合うように符号を決める（候補が1通りに決まるときだけ）、(3) △ の字形を画像で探す（OCR の文字枠の左の小さな三角）。
  (1) は目の単位では必ず決まる。節・説明欄は (2) で決まらないものが残るかもしれない
- 照合: R6 決算の予算現額（款項目別明細表。公開データの決算の `budget_current`）は 当初 + 補正 + 繰越 + 予備費支出・流用増減を足した額なので、
  回の鎖の最後の 計 とは、繰越と予備費支出・流用増減の分だけ違う（予算現額そのものとは突き合わせない。差を繰越だけとみなすと、
  正しい値を不一致と判断する）。決算書類の目の行にある予算現額の内訳（当初予算額・補正予算額…。ノウハウ「自治体データ調査の手順」）の
  補正予算額を取れば突き合わせられる（今の抽出 `kessan-kmk.json` は予算現額・支出済額・翌年度繰越額・不用額だけを持つ。2026-11-15 に確認）
- 議案はテキストなので、款・項の補正額と第1条の追加額・総額は文字で取れる（R8 の6月補正と同じ `extract_hosei.py` の読み方）。
  画像の説明書から取る目の補正額の合計を、議案の項の補正額と照合できる（R8 と同じ検算）。
  **10月専決（第3号）は議案の中身が公開されていない**ので、この照合はできない（12月定例会の第182号議案「専決処分について（令和6年度福岡県
  一般会計補正予算＜第3号＞）」として承認を求めているが、県議会のページは件名だけで、県の予算のページにも議案の PDF はない）。R8 の8月専決と同じく説明書の総括（補正前・補正額・計。画像）に頼るほか、
  前後の回の議案（テキスト）で次のように確かめる（2026-11-20 に議案で確認）:
  総額は 第4号の議案の第1条の補正後の総額 − 第4号の追加額 ＝ 第3号の後の総額 で、第2号の議案の補正後の総額との差が第3号の追加額。
  項は、第4号の議案の第1表の「補正前の額」− 第2号までの計 ＝ 第3号の補正額（第4号で補正した項だけ。それ以外の項は総括と回の鎖で確かめる）
