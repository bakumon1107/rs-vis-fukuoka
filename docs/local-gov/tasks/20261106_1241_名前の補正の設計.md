# 名前の補正の設計（福岡県 R8 当初予算）

状態: **設計（確認待ち）**。実装は承認後に行う。
関連: [共通 JSON 形式の設計](20261106_0841_共通JSON形式の設計.md)（`name_src`）、[作業報告](20261106_0240_データ抽出と検証の作業報告.md) 3.3

## 1. 目的

金額は検算（説明欄・財源・節・項・款・予算書）で正しさを確かめられるが、**名前には検算がない**。画面では名前がそのまま見えるので、
「どの資料で確かめた名前か」を名前ごとに持ち、確かめられない名前を減らす。

## 2. 現状（書き出し 2026-11-06 版）

| 名前 | 件数（目の行ごと） | 今の出典 | 主な崩れ |
|---|---|---|---|
| 一般会計の款 | 14款 | 計上額調（テキスト） | なし |
| 一般会計の項 | 62項（85行が OCR のまま） | R6 決算の項名と照合・残りは議案の文字層 | 「中}子校費」「ゴ;レフ場利用税」 |
| 一般会計の目 | 232＋151（27行が OCR のまま） | R6 決算の目名と照合（崩れとして説明のつくものだけ置き換え） | R8 の新しい目・名前の変わった目 |
| 特別会計の款・項・目 | 112行（すべて OCR・議案の文字層） | 照合先なし | 「積\'金」「北‘同事業拠出金」 |

## 3. 方針

1. **崩れの元を先に直す**（解釈の段階）。2行の名前は、行の中の番号を外してから行にまとめる（目名で直したのと同じ。節・細節・事項にも当てる）。括弧の線（「L」「し」「|」）を名前の先頭から除く
2. **テキストの資料と照合する**（いちばん強い根拠）。崩れとして説明のつく場合だけ置き換える（`is_ocr_variant` の規則。近いだけの別の名前に変えない）

   | 名前 | 照合先（テキスト） |
   |---|---|
   | 一般会計の項 | R6 決算の項名（今もある）、R8 議案の項名（文字層は崩れるので、OCR と一致したときだけ） |
   | 特別会計の款・項 | R8 議案の款・項名 × OCR の見出し（2つが一致・崩れとして説明がつけば採用） |
   | 説明欄の事項 | 施策別資料の事項名（科目＋金額が一致し、名前が崩れとして説明のつくもの）、行政評価の事業名 |
   | 歳入の節 | R6 決算の事項別明細書の歳入の節名（同じ目の中）。目に節が1つだけなら目名 |
3. **独立した読み取りの一致**（2つ目の根拠）。OCR（PP-OCRv6）・文字層・旧 OCR の3つで、正規化した名前が2つ以上一致すれば採用
4. **残りは画像で確かめる**。決まらない名前の一覧（ページ・セルの切り抜き）を作り、目で確かめた名前を修正表に「列: 名前」で記録する

## 4. 名前の出典（`name_src`）の値を増やす

`text`（テキスト資料そのもの）/ `reference`（別資料・別年度のテキストと照合）/ `readings`（独立した読み取りの2つ以上が一致）/
`correction`（画像で確認）/ `ocr`（裏付けなし）。節・細節・事項にも `name_src` を付ける（今は款・項・目だけ）。
節の番号も、読めないものは根拠のあるときだけ埋め、根拠を `no_src`（`ocr` / `textlayer` / `order`＝前後の並び・節が1つだけ）として持つ。

## 5. 確かめ方

- 単体テスト: 実例の崩れ方（2行の名前・括弧の線・置き換えてはいけない例）
- 回帰テスト: 書き出しの要約に「`name_src` ごとの件数」を出し、`ocr`（裏付けなし）の件数の増減を見る
- 画面に出す前の目標: 款・項・目・歳入の節は `ocr` を0件にする。事項・細節は `ocr` の件数を報告し、画面では印を付ける

## 6. 決めてほしいこと

1. 画面に出す前の目標（款・項・目・歳入の節は裏付けなし0件、事項・細節は印を付けて出す）でよいか
2. 画像での確認は、私が切り抜きを見て修正表に書く形でよいか（件数が多いもの＝細節・事項は、まず機械で減らしてから）
