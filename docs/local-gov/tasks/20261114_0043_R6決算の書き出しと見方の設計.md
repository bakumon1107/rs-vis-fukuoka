## 1. 目的と範囲

福岡県の **R6（令和6年度）一般会計・特別会計の決算**を共通 JSON 形式に書き出し、「お金を実際に何に使ったか」をサンキー図で見られるようにする。
R8 当初予算（使う予定）と並べて、予算と決算を切り替えられる画面にする。

範囲（MVP）:
- 一般会計の歳出: 部局 → 款 → 項 → 目 → 節（性質）
- 特別会計の歳出: 8章（部局の表がないので、会計 → 款 → 項 → 目 → 節）
- 歳入（一般会計・特別会計）: 款 → 項 → 目の値をデータに持つが、**図には描かない**（2026-11-14 ユーザー決定）。「データについて」に表で出す
- 公営企業会計の決算は入れない（様式が違う。予算と同じく別に決める）

|---|---|---|---|

## 3. 正規化データ（`settlement-2024.json`）

共通 JSON 形式の設計 4章の決算の項目をそのまま使う。新しく足すのは 3.2 の1つだけ。

### 3.1 行（目）

| 項目 | 歳出 | 歳入 |
|---|---|---|
| `amount` | 支出済額 | 収入済額 |
| `budget_current` | 予算現額（当初予算 + 補正 + 前年度からの繰越 など） | 予算現額 |
| `carried_over` | 翌年度繰越額（継続費逓次繰越・繰越明許費・事故繰越しの計） | — |
| `unused` | 不用額 | — |
| `setsu` | 節（27節の番号と名前は施行規則から）。各節に支出済額・繰越・不用額。細節も持つ | 節は持たない（明細表は目まで） |
| `funding` | 持たない（決算の資料には目ごとの財源内訳がない） | — |
| `items` | 持たない（決算には説明欄の事項がない） | — |

- ID は R8 当初と同じ形（`general/expense/<款>-<項>-<目>`）。**R6 の当初予算は書き出していない**ので、同じ年度の当初と決算で ID を
  そろえる決まり（共通 JSON 形式の設計 3章）は、R6 当初を書き出すときに確かめる
- 歳入の調定額・不納欠損額・収入未済額は `notes` ではなく値として残したい（7章の4）

### 3.2 部局（新しく足す）

**1つの目が複数の部局にまたがる**（R6 で 234目のうち 6目。例: 総務費の一般管理費 = 総務部 + 会計管理局）。
共通 JSON 形式の `department?: { name, via }`（1つだけ）では表せないので、目の行に部局ごとの内訳を持たせる:

```ts
by_department?: { name: string; amount: Value; budget_current: Value; carried_over: Value; unused: Value }[];
```

- 部局ごとの4列の合計 = 目の4列（書き出しと検証で確かめる）
- 節は部局ごとには分かれていない（事項別明細書は目ごと）。図では節を目の右にだけ描くので困らない

### 3.3 実装で決めた細部（2026-11-14）

- **行は歳出の目だけ**（一般会計 234目・特別会計 50目）。歳入は図に描かない（7章の2）ので、行にしない
- **歳入は会計 × 款の表** `revenue_by_kan`（ファイルの項目）で持つ: 収入済額・予算現額・調定額・不納欠損額・収入未済額・過誤納金（内数）。
  特別会計の歳入は概要説明書に款までしかないので、一般会計もそろえて款の単位にする（一般会計の項・目は抽出済みなので、要れば後で足せる）
- **決算の内容・不用額の内容** は目の行の `explanation: { content?, unused? }`。部局をまたぐ目（6目）は部局ごとに文があるので、
  `by_department[]` の各要素にも持たせる（一般会計の目は部局の要素に、特別会計の目は行に持つ）
- **節** は支出済額を `amount` にする（行の `amount` = 支出済額と合わせ、節の合計 = 支出済額を検証できる）。
  節の予算額・繰越・不用額は持たない（要れば型に足す）。**細節は入れない**（事項別明細書の細節の名前の 535/2,008 が文字コードなし・空）
- 出典のページ: 一般会計の目は概要説明書（`r6-kessan-gaiyou`）の明細表のページ、節は事項別明細書（`r6-kessan-jikou`）のページ
- 書き出しは `scripts/local-gov/fukuoka-pref/export_settlement.py`（関数）にし、`export_fukuoka_pref.py` の main から呼んで
  `settlement-2024.json` を書き、`index.json` の datasets に足す（入口を1つにする。index.json を2つのスクリプトで書き分けない）
- 検証（`validate.ts`）: 決算の「予算現額 = 支出済額 + 繰越 + 不用額」は歳出の行だけに当てる。部局の内訳の4列の合計 = 目の4列

## 4. 見方（サンキー図）

**決算の見方**: 部局 → 款 → 項 → 目 → 節（性質）。帯の値は**支出済額**（実際に使った額）。

- 部局 → 款 の帯は、部局ごとの内訳（3.2）から作る（按分しない。資料の数字そのまま）
- 最初に出すのは左の3列（部局 → 款 → 項）。深い列（目・節）は箱を選んだときに開く（予算の見方と同じ決まり。画面とグラフの設計 4.3）
  - 部局・款を選ぶと目まで、項・目を選ぶと節まで（案）
- 節の列は、27節の名前（報酬・給料・委託料・負担金補助及び交付金…）で、「何に使ったか」（人件費・委託・補助金など）が分かる
- 詳細パネル: 支出済額・予算現額・翌年度繰越額・不用額と、執行率（支出済額 ÷ 予算現額）。部局をまたぐ目は部局ごとの内訳
- 0 円の目（予算現額があって支出済額が 0）は帯を描かない。「データについて」の一覧に出す（予算の見方と同じ）

### 4.1 予算と決算の切り替え

- 画面の上に「当初予算（R8）／決算（R6）」の切り替えを置く。いまの年度の切り替え（同じ種類のデータの年度）とは別のつまみ
- URL: `?basis=settlement&year=2024`（なければ最新の当初予算）
- 決算のときは「一般会計／全会計」の切り替えを出さない（一般会計だけ。7章の1）
- 年度が違う（R8 予算と R6 決算）ことを見出しに明示する（「令和6年度 決算（実際に使った額）」）

## 5. 書き出し（`export_fukuoka_pref.py`）

- 回帰テストの作業ディレクトリ（`kessan-kmk.json`・`kessan-bukyoku.json`・`kessan-setsu.json`）から `settlement-2024.json` を作り、
  `index.json` の datasets に `{ year: 2024, basis: "settlement", status: "verified" }` を足す
- 名前は資料のテキストなので `name_src: "text"`。事項別明細書の目の名前の一部は文字コードがない（(cid:N)）が、名前は明細表から取る
- 検算の結果（目の数・一致数・部局と明細表の突き合わせ）を `checks` に入れる

## 6. テスト

- Python: 書き出しの単体テスト（部局の内訳の合計 = 目、節の合計 = 目、ID の形）
- TypeScript: `tests/local-gov-validate.test.ts` に決算のファイルの検証（予算現額 = 支出済額 + 繰越 + 不用額、部局の内訳の合計）、
  グラフのテスト（部局 → 款 の帯の合計 = 支出済額の合計 2兆2,969億円、どの列も合計が同じ）
- 画面: 開発サーバーで切り替え・選択・詳細パネルを確かめる

## 7. 決めたこと（2026-11-14 ユーザー決定）

1. **特別会計の決算も入れる**（8章）
2. **歳入は図に描かない**。左端は部局（一般会計）・会計（全会計）。歳入は「データについて」に款ごとの収入済額などの表で出す
3. **帯の値は支出済額**（実際に使った額）。予算現額・翌年度繰越額・不用額は詳細パネルに数字で出す
4. **歳入の調定額・不納欠損額・収入未済額を正規化データに入れる**（型に `assessed`・`deficit_loss`・`uncollected` を足す。名前は実装のときに
   共通 JSON 形式の設計に合わせて決める）

### 8.1 資料（どちらもテキスト PDF。抽出はこれから）

| 資料 | 載っているもの | 抽出 |
|---|---|---|
| 歳入歳出決算概要説明書（272595）7章「特別会計歳入歳出決算の状況」（PDF 210ページ〜。会計ごとに1〜数ページ） | 歳入: 款ごとの予算現額・調定額・収入済額・不納欠損額・収入未済額。歳出: 款・項の決算額 | 新しく作る（一般会計の款項目別明細表の抽出に近い） |
| 歳入歳出決算事項別明細書（272615）の後半「特別会計歳入歳出決算事項別明細書」 | 目ごとの予算現額・支出済額・繰越・不用額と節 | `extract_kessan_setsu.py` を特別会計にも使えるようにする（一般会計と同じ様式か確かめる） |

- 検算: 一般会計と同じ（目の合計 = 項 = 款、横の式、節の合計 = 目）。会計ごとの歳入合計・歳出合計を概要説明書の「特別会計歳入歳出決算一覧表」と突き合わせる
- 会計の数は R8 当初と同じ 14 のはず（R6 の一覧表で確かめる）

### 8.2 見方

- **部局の表は一般会計にしかない**。特別会計の目は部局が分からないので、決算にも予算と同じく2つの見方を用意する:
  - 一般会計の見方（既定）: 部局 → 款 → 項 → 目 → 節
  - 全会計の見方: 会計 → 款 → 項 → 目 → 節（一般会計も1つの会計として入れる。部局は出さない）
- 予算の全会計の見方の左端（歳入の款）は、決算では描かない（7章の2）ので、左端は会計になる
- 公営企業会計を含まないことを、予算と同じく画面に出す

### 8.3 決めたこと（2026-11-14 ユーザー決定）

1. 決算の全会計の見方の左端は**会計**（会計 → 款 → 項 → 目 → 節）。歳入を描かないので、予算の全会計の見方（歳入の款 → 会計 → …）とは左端が違う
2. 概要説明書の「決算の内容」「不用額の内容」（目ごとの主な内容の文。例「人件費 運営費 財産管理費」「人件費（120,825千円）」）を
   **詳細パネルに出す**（予算の説明欄の事項の代わりに、何に使ったか・なぜ余ったかが分かる）。抽出は済み（一般会計 240行のうち 239行・特別会計 50目）
3. 詳細パネルは、広い画面では図の下に置く（画面とグラフの設計の 2026-11-14 の決定。予算と同じ）
