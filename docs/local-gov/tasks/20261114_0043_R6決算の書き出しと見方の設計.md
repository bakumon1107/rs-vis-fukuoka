## 1. 目的と範囲

福岡県の **R6（令和6年度）一般会計の決算**を共通 JSON 形式に書き出し、「お金を実際に何に使ったか」をサンキー図で見られるようにする。
R8 当初予算（使う予定）と並べて、予算と決算を切り替えられる画面にする。

範囲（MVP）:
- 一般会計の歳出: 部局 → 款 → 項 → 目 → 節（性質）
- 一般会計の歳入: 款 → 項 → 目（図には描かない。「データについて」と詳細パネルで見せる。案。7章の2）
- 特別会計・公営企業会計の決算は入れない（抽出していない。7章の1）

## 2. 使う資料と抽出の状態（抽出・検算は済み。2026-11-06）

| 資料 | 取るもの | スクリプト | 検算（すべて1円まで一致） |
|---|---|---|---|
| 歳入歳出決算概要説明書（272595。テキスト PDF）の款項目別明細表 | 款・項・目の予算現額・支出済額・翌年度繰越額・不用額（歳出）、予算現額・調定額・収入済額など（歳入） | `extract_kessan_kmk.py` | 目の合計 = 項 = 款、横の式（予算現額 = 支出済額 + 繰越 + 不用額 など）、歳入合計・歳出合計 |
| 同じ資料の部局別の表 | 部局 × 款 × 項 × 目 の4列 | `extract_kessan_bukyoku.py` | 部局ごとの合計、全部局の同じ目の合計 = 明細表の目 |
| 歳入歳出決算事項別明細書（272615。テキスト PDF） | 目ごとの節（報酬・給料…の27節）と細節の支出済額・繰越・不用額 | `extract_kessan_setsu.py` | 目ごとに節の合計 = 明細表の予算現額・支出済額（234目すべて） |

R6 の規模: 歳出の予算現額 2兆5,005億円、支出済額 2兆2,969億円、翌年度繰越額 1,534億円、不用額 502億円。歳出の目は 234、部局は 18。

R8 当初予算と違い、**どれもテキスト PDF なので OCR を使わない**。名前・金額の出典は `text`（資料のテキスト）になる。

## 3. 正規化データ（`settlement-2024.json`）

共通 JSON 形式の設計 4章の決算の項目をそのまま使う。新しく足すのは 3.2 の1つだけ。

### 3.1 行（目）

| 項目 | 歳出 | 歳入 |
|---|---|---|
| `amount` | 支出済額 | 収入済額 |
| `budget_current` | 予算現額（当初予算 + 補正 + 前年度からの繰越 など） | 予算現額 |
| `carried_over` | 翌年度繰越額（継続費逓次繰越・繰越明許費・事故繰越しの計） | — |
| `unused` | 不用額 | — |
| `setsu` | 節（27節の番号と名前は施行規則から）。各節に支出済額・繰越・不用額。細節も持つ | 節は持たない（明細表は目まで） |
| `funding` | 持たない（決算の資料には目ごとの財源内訳がない） | — |
| `items` | 持たない（決算には説明欄の事項がない） | — |

- ID は R8 当初と同じ形（`general/expense/<款>-<項>-<目>`）。**R6 の当初予算は書き出していない**ので、同じ年度の当初と決算で ID を
  そろえる決まり（共通 JSON 形式の設計 3章）は、R6 当初を書き出すときに確かめる
- 歳入の調定額・不納欠損額・収入未済額は `notes` ではなく値として残したい（7章の4）

### 3.2 部局（新しく足す）

**1つの目が複数の部局にまたがる**（R6 で 234目のうち 6目。例: 総務費の一般管理費 = 総務部 + 会計管理局）。
共通 JSON 形式の `department?: { name, via }`（1つだけ）では表せないので、目の行に部局ごとの内訳を持たせる:

```ts
by_department?: { name: string; amount: Value; budget_current: Value; carried_over: Value; unused: Value }[];
```

- 部局ごとの4列の合計 = 目の4列（書き出しと検証で確かめる）
- 節は部局ごとには分かれていない（事項別明細書は目ごと）。図では節を目の右にだけ描くので困らない

## 4. 見方（サンキー図）

**決算の見方**: 部局 → 款 → 項 → 目 → 節（性質）。帯の値は**支出済額**（実際に使った額）。

- 部局 → 款 の帯は、部局ごとの内訳（3.2）から作る（按分しない。資料の数字そのまま）
- 最初に出すのは左の3列（部局 → 款 → 項）。深い列（目・節）は箱を選んだときに開く（予算の見方と同じ決まり。画面とグラフの設計 4.3）
  - 部局・款を選ぶと目まで、項・目を選ぶと節まで（案）
- 節の列は、27節の名前（報酬・給料・委託料・負担金補助及び交付金…）で、「何に使ったか」（人件費・委託・補助金など）が分かる
- 詳細パネル: 支出済額・予算現額・翌年度繰越額・不用額と、執行率（支出済額 ÷ 予算現額）。部局をまたぐ目は部局ごとの内訳
- 0 円の目（予算現額があって支出済額が 0）は帯を描かない。「データについて」の一覧に出す（予算の見方と同じ）

### 4.1 予算と決算の切り替え

- 画面の上に「当初予算（R8）／決算（R6）」の切り替えを置く。いまの年度の切り替え（同じ種類のデータの年度）とは別のつまみ
- URL: `?basis=settlement&year=2024`（なければ最新の当初予算）
- 決算のときは「一般会計／全会計」の切り替えを出さない（一般会計だけ。7章の1）
- 年度が違う（R8 予算と R6 決算）ことを見出しに明示する（「令和6年度 決算（実際に使った額）」）

## 5. 書き出し（`export_fukuoka_pref.py`）

- 回帰テストの作業ディレクトリ（`kessan-kmk.json`・`kessan-bukyoku.json`・`kessan-setsu.json`）から `settlement-2024.json` を作り、
  `index.json` の datasets に `{ year: 2024, basis: "settlement", status: "verified" }` を足す
- 名前は資料のテキストなので `name_src: "text"`。事項別明細書の目の名前の一部は文字コードがない（(cid:N)）が、名前は明細表から取る
- 検算の結果（目の数・一致数・部局と明細表の突き合わせ）を `checks` に入れる

## 6. テスト

- Python: 書き出しの単体テスト（部局の内訳の合計 = 目、節の合計 = 目、ID の形）
- TypeScript: `tests/local-gov-validate.test.ts` に決算のファイルの検証（予算現額 = 支出済額 + 繰越 + 不用額、部局の内訳の合計）、
  グラフのテスト（部局 → 款 の帯の合計 = 支出済額の合計 2兆2,969億円、どの列も合計が同じ）
- 画面: 開発サーバーで切り替え・選択・詳細パネルを確かめる

## 7. 決めてほしいこと

1. **特別会計の決算も入れるか**。MVP は一般会計だけ（案）。入れるなら、決算書（議案 272758）から特別会計の款・項・目を抽出する作業が増える
   （テキスト PDF かどうかは未確認）
2. **歳入を図に描くか**。案は描かない（左端は部局）。歳入は「データについて」に款ごとの収入済額の表で出す
3. **帯の値**: 支出済額（実際に使った額。案）か、予算現額（使えた額）か。不用額・繰越を別の色の帯で見せる案もあるが、MVP では詳細パネルに数字で出す
4. **歳入の調定額・不納欠損額・収入未済額**を正規化データに入れるか（型に項目を足す）。案は入れる（決算の歳入では大事な数字なので）
