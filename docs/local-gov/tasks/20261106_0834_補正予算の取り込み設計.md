# 補正予算の取り込み 設計書

状態: **承認済み（2026-11-06）**。8章の3点とも案どおり。
関連: [福岡県予算ビュー計画書](20261106_0122_福岡県予算ビュー計画書.md)（6章「補正予算の扱い」の未決事項）、[作業報告](20261106_0240_データ抽出と検証の作業報告.md)

## 1. 目的

当初予算だけでは、年度途中に追加・減額された予算（物価高騰対策・災害対応・国の経済対策など）が見えない。
県の予算は年に数回の補正で数百億〜数千億円動く（R6 9月補正の一般会計だけで 105億円の追加）。次の3つを見せられるようにする。

1. **予算の流れ**: 当初予算 → 各回の補正 → 最終予算（補正後）→ 決算（実際に使った額）
2. **補正の中身**: その回の補正で、どの款・項・目・事項に、いくら足した（減らした）か
3. **補正の性格**: 定例会の補正・追加提案分・専決処分（知事が議会を開かずに決めたもの。後で議会が承認）の区別

## 3. データの持ち方（共通 JSON 形式への追加）

補正は**差分**として持ち、補正後は計算で出す（二重に持たない）。

```
予算（年度・会計）
  当初: 款 → 項 → 目 → 事項（金額）
  補正: [
    { 回: "R8-06", 種別: 定例 | 追加提案 | 専決, 議案番号, 提出日・専決日, 出典ファイル,
      款 → 項 → 目 → 事項（補正額。減額は負）, 財源内訳（補正額の） }
    ...（時系列）
  ]
  補正後（計算）: 当初 + Σ補正。目・事項の単位で
```

- 事項の対応: 補正の説明欄の事項は当初にない新しい事項のことが多い（例「○物価高騰対応重点支援地方創生臨時交付金」）。当初の事項と名前で対応が付けば足し込み、付かなければ「補正で追加された事項」として別に持つ
- 金額の出典（OCR・文字層・テキスト・修正表）は当初と同じく値ごとに持つ

## 4. 抽出の方式

| 対象 | 方式 | 既存の部品 |
|---|---|---|
| 議案の第1表（款・項） | テキスト（pdfplumber の単語）。列は 補正前の額・補正額・計 の3つ | `extract_yosansho.py` を補正の様式に対応させる（列が3つ。第1条の「追加し…とする」） |
| 説明書（テキスト） | pdfplumber の単語の座標で列を切る（当初の OCR と同じ表の解釈に載せる） | 新規: テキストから `ocr_pages.py` と同じ形式を作る変換。解釈は `parse_setsumeisho.py` を補正の列に対応させる |
| 説明書（画像） | OCR（PP-OCRv6）＋文字層があれば突き合わせ | `ocr_pages.py`・`textlayer_pages.py`・`cross_check.py` |

`parse_setsumeisho.py` は列の意味（本年度・前年度・比較 ↔ 補正前・補正額・計）を引数で切り替える。当初の解釈を変えないことを回帰テストで確かめる。

## 5. 検算（すべて完全一致を要求）

目ごと（説明書）:
- 補正前の額 + 補正額 = 計
- 説明欄の合計・節の合計・財源内訳の合計 = 補正額

項・款（説明書と議案）:
- 目の合計 = 議案の第1表の項（補正前・補正額・計の3つとも）
- 項の合計 = 款、款の補正額の合計 = 第1条の追加額

回をまたぐ照合（**補正ならではの強い検算**）:
- **前の回の「計」= 次の回の「補正前の額」**（同じ年度の補正を時系列に並べると鎖になる）
- **最初の回の「補正前の額」= 当初予算**（当初予算の OCR 結果の独立した確認にもなる。R8 6月補正の国庫補助金の補正前 8,819,677 千円 = R8 当初 で確認）
- **最後の回の「計」= 決算の「当初予算額 + 補正予算額」**（R6 決算の事項別明細書の目の行に、当初予算額・補正予算額が別々に印字されている。この列は今は数字が詰まっていて読んでいない → 文字の座標で読む改修が必要）

## 6. 回帰テストへの影響

- 単体テスト: 補正の列の解釈、回の鎖の照合、事項の対応付け（実例の崩れ方を再現した入力）
- 回帰テスト（`tests/regression.py`）に、補正の議案・説明書のステップを足す。当初予算のステップの期待値が**変わらないこと**を確かめてから足す

## 7. 進め方（案）

| 段階 | 内容 | 規模 |
|---|---|---|
| 1 | R8 の補正（議案4回分と、テキストの説明書3回分）を抽出・検算。9月第3号（画像）は OCR＋文字層 | 小〜中（テキストが中心） |
| 2 | 共通 JSON 形式に「補正」を入れる（全体の形式設計に含める） | 共通 JSON 形式の設計書で扱う |

| 4 | 画面: 当初・補正後・決算の切り替え、補正の回ごとの差分の表示 | 画面の設計書で扱う（2026-11-07 時点の画面の設計は当初予算だけ。切り替えは補正の取り込み・決算の書き出しのときに足す） |

画面は「当初予算」と「最新の補正後予算」の切り替えまでを MVP に入れ、回ごとの差分の表示は MVP の後にする。
（2026-11-07 補足: MVP の範囲は変えない。画面は当初予算から作り、補正後への切り替えは補正の取り込みと一緒に足す。8章の1）

## 8. 決めたこと（2026-11-06）

1. MVP の範囲: データは最初から補正を持てる形にする。画面は「当初予算」と「最新の補正後」の切り替えまで（回ごとの差分の表示は MVP の後）
   → **2026-11-07 補足**（[画面とグラフの設計](20261106_1327_地方版サンキー図の画面とグラフの設計.md) 1章）: この決定（MVP の範囲）は変えない。
   画面は当初予算から作り、「最新の補正後」への切り替えは補正の取り込み（当初 + Σ補正 の組み立て）と一緒に足して MVP をそろえる。データの形も変えない
2. 年度: まず R8（最新、テキスト中心）。次に R6（決算と照合できる）
3. 専決処分: 補正の1回として同じに扱い、印（種別: 専決）を付ける
