## 1. 目的と範囲

自治体ごとのデータパイプライン（福岡県は `scripts/local-gov/fukuoka-pref/`。PDF・OCR・文字層から抽出して検算）が出力し、
地方版の画面が読む **JSON の形を1つに決める**。2件目の自治体（市区町村を含む）でも同じ形に載せられることを目標にする。

範囲:
- 予算（当初・補正）と決算。一般会計・特別会計・公営企業会計
- 階層: 会計 → 款 → 項 → 目 → 事項（予算の説明欄）／節（性質）。歳入と歳出
- 値ごとの出典（どの読み取りで得た値か）と検算の結果
- 画面のための派生データ（サンキー図のグラフ）

範囲外（別の設計書で扱う）: 画面の作り、行政評価・施策別資料との紐付けの方法の詳細、契約（支出先）。

## 2. 国版の形から学ぶこと（2026-11-06 確認）

| 国版 | 地方版での扱い |
|---|---|
| 2段構え: 正規化データ（目の行の一覧。`types/mof-kou-moku.ts`）→ 年度×基準ごとの**グラフのファイル**（`unified-budget-{年度}-{基準}-graph.json`）を事前に作り、画面はグラフだけを読む | **同じ2段構えにする**。正規化データは検算・再利用のため、グラフは画面を軽くするため |
| 階層は入れ子でなく、行の項目（所管・組織・項・目）として持つ | 正規化データも**平らな行の一覧**にする（集計・絞り込み・差分が書きやすい）。入れ子は生成時に作る |
| 金額は円（予算書の千円は変換） | **円の整数**で持つ。元の単位は `unit_source` に書く |
| 基準（当初・補正・決算）は別ファイル。当初と補正の目の ID が一致しないので混ぜない | 基準は別ファイル。ただし地方版は**同じ年度の目の ID を基準間でそろえる**（補正は目の単位の差分なので、そろえられる） |
| グラフの列は国固有の9種で固定（`UnifiedColumn`）。描画部品は列名に強く依存 | 地方版の列は**データ側で定義**する（列の一覧をグラフのファイルに持たせる）。描画は国版の下の層（ノード・リンク・配置）だけ再利用 |

## 3. ファイルの構成

```
public/data/local-gov/<自治体ID>/
  index.json                         … 自治体の情報・使える年度と基準の一覧・資料の一覧（3.1）
  budget-<年度>-initial.json         … 正規化データ: 当初予算（4章）
  budget-<年度>-supplementary-<回>.json … 正規化データ: 補正（差分。補正の設計書）
  settlement-<年度>.json             … 正規化データ: 決算
  graph-<年度>-<基準>.json           … 画面用のグラフ（5章）。基準 = initial / latest（最新の補正後）/ settlement
```

- 自治体 ID はローマ字の slug（`fukuoka-pref`、市区町村は `fukuoka-city` など）。年度は西暦の数値（`2026`）と和暦の表示（`令和8年度`）を両方持つ
- **圧縮せず JSON のまま**コミットする（計画書 4章の決定）。正規化データは整形（インデント 1）、グラフは改行なし
- `schema_version` を全ファイルに持つ（形を変えたら上げる。画面は知らない版を読んだら表示を止めて知らせる）

### 3.1 index.json

```jsonc
{
  "schema_version": 1,
  "gov": { "id": "fukuoka-pref", "name": "福岡県", "kind": "prefecture",
           "population": [{ "value": 5_000_000, "as_of": "2026-01-01", "source": "住民基本台帳（…）" }] },
  "datasets": [
    { "year": 2026, "label": "令和8年度", "basis": "initial", "file": "budget-2026-initial.json", "status": "verified" },
    { "year": 2024, "label": "令和6年度", "basis": "settlement", "file": "settlement-2024.json", "status": "verified" }
  ],
  "sources": [
    { "id": "r8-setsumeisho-ippan", "title": "令和8年度当初予算に関する説明書（一般会計）",
      "url": "https://www.pref.fukuoka.lg.jp/uploaded/attachment/281298.pdf", "sha256": "…", "retrieved": "2026-11-05" }
  ]
}
```

- `population` は1人あたり換算に使う（事例調査 3章）。時点と出典を必ず書く（数字はここでは仮）
- `status`: `verified`（全検算一致）/ `partial`（一致しない箇所あり。画面に注意を出す）

## 4. 正規化データ（予算・決算）

### 4.1 形（TypeScript の型で書く。`types/local-gov.ts` に置く）

```ts
type Yen = number;                       // 円の整数（千円の資料は ×1000）

interface LocalBudgetFile {
  schema_version: 1;
  gov_id: string;
  year: number; year_label: string;
  basis: 'initial' | 'supplementary' | 'settlement';
  supplementary?: { round: string; kind: '定例' | '追加提案' | '専決'; bill_no?: string; date?: string };
  unit_source: '千円' | '円';
  accounts: Account[];                   // 会計の一覧（行から参照する）
  rows: MokuRow[];                       // 目の行（平ら）
  checks: CheckSummary;                  // 検算の結果の要約（4.4）
}

interface Account {
  id: string;                            // 'general' / 'special:kokumin-kenko-hoken' / 'enterprise:byoin'
  kind: 'general' | 'special' | 'enterprise';
  name: string;                          // 一般会計 / 国民健康保険特別会計 / 病院事業会計
}

interface MokuRow {
  id: string;                            // 4.2
  account: string;                       // Account.id
  side: 'revenue' | 'expense';
  enterprise_section?: '収益的' | '資本的'; // 公営企業会計だけ
  kan: { no: number; name: string };
  kou: { no: number; name: string };
  moku: { no: number; name: string };
  amount: Value;                         // 本年度（予算）／補正額（補正）／支出済額（決算）
  previous?: Value;                      // 前年度（当初予算）
  before?: Value; after?: Value;         // 補正前・計（補正）
  budget_current?: Value; carried_over?: Value; unused?: Value;  // 予算現額・翌年度繰越額・不用額（決算）
  funding?: { national: Value; bond: Value; other: Value; general: Value };  // 財源内訳（歳出）
  items?: Item[];                        // 説明欄の事項（予算）
  setsu?: Setsu[];                       // 節（予算・決算）
  department?: { name: string; via: string };  // 部局（決算の部局別の表、または事項の課名から）
  notes?: string[];                      // 「○○課所管」「事業費支弁職員 2人」などの注記
  pages: { source: string; page: number }[];   // 出典の資料（index.sources の id）とページ
}

interface Item {                         // 説明欄の ○事項
  name: string; amount: Value;
  parent?: number;                       // 入れ子の内訳は親の添字
  headcount?: number;                    // 「職員費 293人」
  no_amount_printed?: boolean;           // 1事項で金額の記載なし（目の額を当てた）
  links?: { kind: '施策別資料' | '行政評価'; id: string; match: 'amount+name' | 'name' }[];
}

interface Setsu { no: number; name: string; amount: Value; sub?: { name: string; amount: Value }[] }

interface Value {
  v: Yen | null;
  src: 'text' | 'ocr' | 'textlayer' | 'correction' | 'blank-as-zero' | 'inferred';
  agree?: number;                        // 同じ値を出した読み取りの数（多数決。OCR の資料だけ）
  note?: string;                         // 修正表の根拠など
}
```

- **値ごとに出典**（`src`）を持つ。画面で「推定」「画像で確認して修正」の印を出せるようにする（事例調査: 佐久市は推計を明記）
  - `blank-as-zero`: 空欄を 0 とみなした（|本年度 − 前年度| = |比較| が成り立つときだけ）
  - `inferred`: 検算の式から逆算（裏付けのない推定。原則として使わず、使えば `status: partial`）
- 大きさの目安: 福岡県 R8 一般会計で目 383・事項 約1,000・節 約2,000。出典を値ごとに持つと 1〜2MB（圧縮しない方針の範囲）

### 4.2 ID の付け方

`<会計ID>/<歳入歳出>/<款>-<項>-<目>`（例 `general/expense/2-1-1`）。

- 番号は**その年度の番号**（目番号は年度で変わる。R6 の 2款1項3目「広報費」は R8 では「文書費」）。ID は年度の中でだけ一意
- 同じ年度の当初・補正・決算では同じ目に同じ ID（補正・決算は当初の目を参照できる）
- **年度をまたぐ対応**は ID でなく、別の対応表（`crosswalk-<年度A>-<年度B>.json`、名前と金額で作る）で持つ。前年比較・推移はこれを使う

### 4.3 会計間の重複（純計）

一般会計の繰出金と特別会計の繰入金（例: 公債管理特別会計への繰出 228,089,882 千円）は、全会計を足すと二重になる。
- 目の行に `transfer?: { to_account: string }` / `{ from_account: string }` を付ける（款・目の名前と相手の会計から判定。判定の規則は自治体設定に書く）
- グラフの生成時に「総計（単純合計）」と「純計（重複を除く）」を選べるようにする（国版の gross / net と同じ考え方）

### 4.4 検算の結果（`checks`）

```jsonc
{ "rows": 383, "all_ok": 383,
  "rules": { "A_説明欄": 383, "B_財源": 232, "C_比較": 383, "D_節": 383 },
  "external": { "項_予算書": "106/106", "款_計上額調": "29/29", "計の行": "74/74" },
  "readings": { "agree_2plus": 0.997 },       // 多数決で2通り以上が同じ値だった割合
  "corrections": 4 }
```

画面の「説明と出典」ページはここを読んで表示する（事例調査 3章）。

## 5. 画面用のグラフ（graph-<年度>-<基準>.json）

```ts
interface LocalGraph {
  schema_version: 1; gov_id: string; year: number; basis: 'initial' | 'latest' | 'settlement';
  columns: { key: string; label: string }[];   // 例: 財源 / 会計 / 款 / 項 / 目 / 事項。データ側で定義する
  nodes: { id: string; col: string; name: string; value: Yen; row?: string; flags?: string[] }[];
  edges: { source: string; target: string; value: Yen }[];
  totals: { gross: Yen; net: Yen };
}
```

- 列の候補（自治体設定で選ぶ）:
  - 予算: 財源（一般財源・国庫支出金・地方債・その他）→ 会計 → 款 → 項 → 目 → 事項
  - 決算: 部局 → 款 → 項 → 目 → 節（性質）
  - 左端を「歳入の款」にするか「財源」にするかを切り替えられるようにする（事例調査: 文京区・佐久市は財源）
- `row` で正規化データの目に戻れる（詳細パネル）。`flags` は `inferred`・`corrected`・`transfer` など
- 事項の数が多い目は上位 N 件＋「その他」にまとめる（生成時でなく画面で。国版の TopN と同じ）
- `basis: 'latest'` は 当初 + Σ補正 を生成時に計算したもの（補正の設計書）

## 6. 作り方（パイプラインとの境目）

```
scripts/local-gov/<自治体>/  … 抽出・検算（自治体ごと。Python）。中間結果はスクラッチ（コミットしない）
        ↓ export_<自治体>.py: 正規化データ（4章）を書き出す
public/data/local-gov/<自治体>/budget-*.json  … コミットする
        ↓ scripts/local-gov/generate-graph.ts（共通。TypeScript）
public/data/local-gov/<自治体>/graph-*.json   … コミットする
```

- 自治体ごとの部分は **export まで**。グラフの生成以降は共通（2件目の自治体は export を書くだけで画面に載る、を目指す）
- 正規化データの検証（型・合計・ID の一意性・会計の参照）は共通の TypeScript のテストで行う（`npm test` に入れる。`tests/local-gov/*.test.ts`）
  - 例: 目の合計 = `checks` の値、`all_ok` の行数、ID の重複なし、`src: inferred` があれば `status: partial`

## 7. 回帰テストへの影響

- Python 側の回帰テスト（`scripts/local-gov/fukuoka-pref/tests/regression.py`）に export のステップを足し、**正規化データの要約**（目の数・総額・`checks`）を期待値に入れる
- TypeScript 側: 生成したグラフの要約（列ごとの合計・ノード数）をスナップショットとして持ち、生成ロジックを変えたら差分を確かめる
- `schema_version` を上げるときは、旧版のファイルを読めないことを確かめるテストを足す

## 8. 決めてほしいこと

1. **2段構え**（正規化データ＋グラフ）と、**正規化データもコミットする**方針でよいか（グラフだけにすると小さいが、検算・再利用ができなくなる）
2. **値ごとの出典**（`src`）を持つか（ファイルは 2倍程度になるが、画面で推計・修正の印を出せる）
3. グラフの左端の既定: 「財源」か「歳入の款」か（切り替えは両方用意する前提）
4. 純計（会計間の重複を除く）を MVP に入れるか（一般会計だけなら不要。特別会計も載せるなら必要）
