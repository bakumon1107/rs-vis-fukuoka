# 福岡県予算ビュー 計画書

作成: 2026-11-06
状態: 計画（合意待ち）
前提: [地方版予算ビュー全体計画](20261106_0111_地方版予算ビュー全体計画.md)

## 1. 目的

福岡県が公開している既存データだけを使って、県予算の流れを可視化する「福岡県予算ビュー」を作る。
国版（RS システム）の「会計 → 所管 → 項 → 目 → 事業 → 支出先」サンキー図に相当するものを、
県の予算書の構造「会計 → 款 → 項 → 目 → 事業（説明欄）」で再現し、行政評価（事務事業評価）を事業の詳細情報として結び付ける。

## 2. 公開データの棚卸し（2026-11-06 調査）

（以下のパスはすべて `https://www.pref.fukuoka.lg.jp` 配下）

### 2.1 予算に関する説明書（主データ源）

掲載ページ: `/contents/yosanngiann.html`。**平成25年度〜令和8年度**の当初・補正がそろっている。

| 資料（R8当初） | パス | 規模 |
|---|---|---|
| 当初予算議案 | `/uploaded/attachment/281297.pdf` | 6.5MB |
| 当初予算に係る説明書（一般会計） | `/uploaded/attachment/281298.pdf` | 22MB・482ページ |
| 当初予算に係る説明書（特別会計・公営企業会計） | `/uploaded/attachment/281299.pdf` | 11MB |
| （参考）R7当初 一般会計 / 特別・企業 | `259281.pdf` / `259282.pdf` | |

**構造**（R8一般会計 192ページ目で確認）: 款・項ごとの表で、列は次のとおり。

- 目（名称）／本年度／前年度／比較
- 本年度の財源内訳: 特定財源（国庫支出金・地方債・その他〔使用料及び手数料・諸収入など〕）／一般財源
- 節（細節）: 区分（1報酬・3職員手当等・8旅費 … 18負担金補助及び交付金 など）／金額
- **説明: 「○事業名 金額」の列挙**（例: ○国民健康保険助成費 17,773,509、○国民健康保険特別会計への操出金 29,912,902）

単位は千円（アプリ内部では1円単位に換算する）。

→ **会計 → 款 → 項 → 目 → 説明欄の事業** までの階層と金額が取れる。財源内訳（国費・県債・一般財源）と性質（節）も取れる。

**課題: PDF はスキャン画像（150dpi・JPEG2000）に OCR のテキスト層が付いたもので、テキスト層は使えない品質**（縦書き混じりで数字が分断・誤認識される）。
再 OCR（表構造を考えた方法）が必要。これがこの計画で最大の技術リスク。

## 3. 可視化の設計方針

### 3.1 サンキー図の階層

```
会計（一般会計 / 特別会計14 / 公営企業会計）
  → 款（14款）
    → 項
      → 目
        → 事業（説明欄の ○事業名）
```

- 別のビューまたは切り替えとして、**財源（国庫支出金・地方債・その他特定財源・一般財源）→ 款** の流れも出せる（説明書の財源内訳列を使う）
- 節（性質: 人件費・補助金・委託料など）は詳細パネルに表示する
- 会計間の繰り出し（例: 一般会計 → 国民健康保険特別会計への繰出金）は二重計上になるため、純計の扱いを決める（未決事項）

### 3.2 行政評価との紐付け

- 事業ノード（説明欄の事業名）と事務事業評価の事業名を照合し、詳細パネルに成果指標・見直し区分・事業費の推移を出す
- 名称は完全一致しないことが多い想定（評価書は「○○事業」、説明欄は「○○費」など）。正規化して照合し、残りは手動の対応表で補う
- 評価書の事業費（R8当初・千円）と説明欄の金額の一致を、照合が正しいかの確認に使う

### 3.3 対象年度

- MVP は **令和8年度当初予算**（最新。行政評価 R7 の「R8当初」事業費と突き合わせられる）
- 次に R7 当初を加えて前年比較（説明書の「前年度」列でも可）

## 4. データパイプライン

`scripts/local-gov/fukuoka/` 配下（国版の `scripts/` とは分ける）。

1. **取得**: 公式 PDF をダウンロード（リポジトリにはコミットしない。URL と SHA256 を記録）
2. **計上額調の抽出**（テキスト PDF）→ 会計別・款別の総額（検算用の基準値）
3. **説明書の OCR → 表の復元**
   - 候補A: 罫線検出でセルを切り出して OCR（tesseract jpn など）
   - 候補B: 視覚対応 LLM でページ画像から JSON へ変換（ページ数は一般会計 約480・特別/企業会計 約250。コストと精度を比べる）
   - どちらでも、**数値は検算で正しさを担保する**: 目の合計＝項、項の合計＝款、款の合計＝計上額調、財源内訳の合計＝本年度、節の合計＝目、説明欄の合計＝目（説明欄が全額を列挙しているかは要確認）
4. **行政評価データの取り込み**: `mirai-gikai-fukuoka-pref` の JSON をコピーまたは参照（取り込み方は未決事項）
5. **JSON 生成** → 国版と同じく `.gz` で Git 管理

## 5. アプリ側の改修方針

- 国版のハードコード（総額・所管・RS 事業 ID・文言・URL）を棚卸しし、**自治体設定**（名称・年度・データパス・階層ラベル「所管→款」など）に寄せる
- 階層の名前と段数を設定で持てるようにする（国: 所管/項/目/事業/支出先、県: 款/項/目/事業）
- 使わない画面（`/fiscal-space`・`/tax-burden`・`/subcontracts` など）は地方版のナビゲーションから外す（コードは残して本家との差分を小さくする）

## 8. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| 説明書の OCR 精度 | 金額の誤りは信頼を損なう | 階層の合計による検算をすべて通す。通らないページは手で直して記録する |
| 説明欄が目の全額を列挙していない | 事業ノードの合計が目と合わない | 差額を「その他（事業名なし）」ノードにまとめる |
| 年度で様式が変わる | 過年度展開の工数が増える | MVP は R8 のみ。過年度は様式を確認してから |
| 行政評価と事業名が一致しない | 紐付け率が低い | 正規化＋手動対応表。紐付けは任意の付加情報として扱う |
