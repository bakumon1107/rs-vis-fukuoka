# 名前の読み取りに NDLOCR-Lite を組み込む設計（福岡県 R8 当初予算の説明書）

状態: **承認（2026-11-14 ユーザー。8章はすべて案のとおり。Tesseract は NDLOCR-Lite の結果を見てから決める）**

関連: [OCR の別ツール検証の設計](20261114_1301_OCRの別ツール検証の設計.md)（5.4 の提案1を承認済み: 名前の読み取りに NDLOCR-Lite を足す。金額は今のまま）、
[データの作り方](../fukuoka/データの作り方.md)、`scripts/local-gov/fukuoka-pref/name_evidence.py`（名前の選び方）

## 1. 目的

今の名前の候補は、PP-OCRv6（新）と PP-OCRv4（旧）と説明書の文字層の3つ。新と旧は同じ系統（PaddleOCR）で同じ字を一緒に読み違えるので、
1つの系統として数えている（`name_evidence.resolve` の「系統」）。名前の裏付け（出典 readings）は「別の系統の2つが一致」なので、
実際には **OCR と文字層の2つ**でしか決まらず、文字層の崩れた名前では OCR の読み違いがそのまま残る（出典 ocr）。

検証（5.1・5.2）では、系統の違う NDLOCR-Lite の文字の認識（PARSeq）が名前に強く（事項 324件で new 293 → ndl 307）、
多数決に入れると「一致して誤る」件数が減った（new・v4・ndl で誤 6 → new・ndl・tess で誤 2）。
これを3つ目の系統として名前の候補に足し、**裏付けのある名前を増やし、一致して誤った名前を見つける**。

## 2. 範囲

| 対象 | 入れるか | 理由 |
|---|---|---|
| 目の名前・説明欄の事項・細節・歳入の節の区分 | **入れる** | 名前の読み違いが残るところ（検証で効果を確かめた） |
| 歳出の節の名前 | 入れない | 節の番号で決まる（今のまま） |
| 款・項の名前 | 入れない | 予算書の本体（議案）・R6 決算の名前で裏付けがある |
| 金額 | 入れない | NDLOCR-Lite は数字に弱い（5.3）。今の多数決と検算のまま |
| 9月補正（第3号）の画像の回 | **次の段**（8章の2） | 書き出しの名前の選び方が当初と別（`export_hosei.py`）。今回の当初で効果を確かめてから |

対象の資料: R8 一般会計の説明書（281298）・特別会計の説明書（281299）。どちらも今の OCR と同じ 300dpi のページ画像を読む。

## 3. 仕組み

### 3.1 読み取り（新しいスクリプト `ocr/ndl_pages.py`）

- 入力: 原本の PDF、今の OCR の結果（`ocr/r8-ippan/pNNNN.json`。表の縦線・欄ごとの文字枠）
- 出力: **OCR の結果と同じ形のページ**（`$D/ocr/r8-ippan-ndl/`・`r8-toku-ndl/`。名前の欄の金額でない文字枠だけを、行ごとに NDLOCR-Lite で読んだ文字に
  置き換える。`textlayer_pages.py` と同じ考え方）。これを今と同じ `parse_setsumeisho.py` にかけると、金額は OCR と同じで名前だけが違う読み取り
  （`setsumeisho-ndl.json`）ができる。OCR と同じく保存した結果を回帰テストの入力にする（読み直しは約25分かかるので毎回は流さない）
- 切り抜き: 行の高さは OCR の文字枠の帯。横は OCR の文字枠の両端から字の約1個分広げる（節の区分の欄は欄の幅いっぱい）。ただし欄の縦線の内側・
  同じ行の金額の左まで、名前の左の数字だけの文字枠（番号）の右から（9章）。2行に折り返す名前は行ごとに読み、解釈がつなぐ
- 認識: 同梱の PARSeq の ONNX モデル3つ（30字・50字・100字）と文字表を onnxruntime で動かす（検証と同じ。前処理・後処理は NDLOCR-Lite の
  `src/parseq.py` に倣う）。字間の広い名前は空白の列を詰めてから読む（検証の `squeeze_gaps`）
- 速さ: 1行数ミリ秒。2冊（約500ページ）の名前で数分

### 3.2 名前の選び方（`export_fukuoka_pref.py`）

- 名前の候補に、NDLOCR-Lite の読み取りを**別の系統 `ndl`** として足す（今の `others()` に 文字層・旧 に並べて加える。対応の付け方も同じで、
  事項・節は目の中の金額で対応させる）
- 系統が ocr・textlayer・ndl の3つになるので、文字層が崩れていても、OCR と NDLOCR-Lite が一致すれば readings（裏付けあり）になる
- （実装で変えた）NDLOCR-Lite は一致の支えにだけ使い、疑いの根拠・採る名前にはしない（9章）
- 字形の直し（`GLYPH_FIXES`・`WORD_FIXES`）は今の読み取りと同じに当てる

## 4. 置き場所とライセンス

- **NDLOCR-Lite のコード・モデル・文字表はリポジトリに入れない**。環境変数 `NDLOCR_LITE_DIR` で場所を指す
  （手元は `~/data/rs-vis-fukuoka/alt-ocr/ndlocr-lite`。github.com/ndl-lab/ndlocr-lite の 2026-11-11 版 a25d456）。依存（onnxruntime・opencv・pyyaml）は今の `PYLIB` に入っている
- 使うのは **PARSeq の3モデルと文字表（`src/config/NDLmoji.yaml`）だけ**（CC BY 4.0）。配置の検出モデル（DEIM。DINOv3 のライセンスが掛かる）は使わない。
  NDLOCR-Lite の Python コードは実行も複製もしない（前処理・後処理は自分で書く）
- 帰属の表示（CC BY 4.0）: 次の3か所に「国立国会図書館『NDLOCR-Lite』（CC BY 4.0）」と出典の URL を書く
  1. 画面の「データについて」の資料・作り方の節（名前の読み取りの一部に使ったこと）
  2. `ocr/ndl_pages.py` の冒頭（前処理・後処理を `parseq.py` に倣ったこと）
  3. `docs/local-gov/fukuoka/データの作り方.md`（入れ方・版）
- 読み取りの結果（`setsumeisho-ndl.json`）は作業ディレクトリに置き、コミットしない（今の OCR の結果と同じ）

## 5. 回帰テスト

- ステップ「NDLOCR-Lite の解釈」を足す（一般会計・特別会計）。入力は保存した `ocr/r8-ippan-ndl`・`ocr/r8-toku-ndl`（OCR と同じく回帰テストでは
  読み直さない。/code-review の指摘で、毎回 25分かかる読み直しをやめた）。なければこのステップと書き出し・補正の照合を飛ばす
  （NDLOCR-Lite の結果のない環境で、名前の違う公開データを作らない）
- 期待値は、解釈の要約と、書き出しの名前の出典の件数（`名前の出典:` の行）

## 6. 公開データへの影響と確かめ方

名前の出典の件数が変わる（ocr が減り readings が増える見込み）。**名前の字が変わるもの**は、全部を画像で確かめてから公開データに入れる:

1. 組み込む前と後の公開データを比べ、名前の字が変わったもの・出典が readings から ocr に下がったもの（一致して誤っていた疑い）を一覧にする
2. 一覧の名前を、ページ画像の切り抜きで確かめる（9月補正のときと同じやり方）
3. NDLOCR-Lite の読みが正しくても採られなかった名前・逆に誤って採られた名前は、名前の修正表（`ocr/corrections/r8-names.json`）に画像の名前を記録する

見込み（検証の数字から）: 事項は裏付けのない名前が 30件ほど減り、一致して誤っていた名前が数件見つかる。細節は欄の幅で切り抜くので、検証より良くなる見込み。

## 9. 実装の結果（2026-11-15）

- `ocr/ndl_pages.py`: 名前の欄の金額でない文字枠を行ごとに読み直す。切り抜きは、説明欄・目の欄は OCR の文字枠の両端から字の約1個分
  （行の高さ × 1.2）、節の区分の欄は欄の幅いっぱい（字間の広い細節）。欄の端まで広げると説明欄の名前の端に記号のごみが付いた
  （「○会計事務費(一」）ので、この形にした。2冊（一般会計 412ページ・特別会計 128ページ）で約25分
- **NDLOCR-Lite は一致の支えにだけ使う**（`name_evidence.resolve` の `support_only`）。最初は他の系統と同じに扱ったが、2行の名前
  （歳入の節の区分・目の名前）で隣の番号や記号を端に読み込み（「の用水事業費2負担金」「丘流域下水道3事業繰入金」）、
  「字を足した読み取り＝OCR が字を落とした疑い」として正しい名前 17件を読み取りのみに下げた。広く切り抜くので、字を足した形は
  疑いの根拠にならない。NDLOCR-Lite だけが読んだ名前も採らない（支えにだけ数える）
- 公開データ: 名前の値・出典とも変わらない（今の公開データは、読み取りのみの名前を画像で確かめて修正表で埋めてある）
- **数字・短い行は OCR の読みのまま**（/code-review と実データで見つかった。2026-11-15）:
  - 目の欄の「計」の行は置き換えない（1字の「計」を横に引き伸ばして「10」「11」と読み、解釈が計の行を見分けられず架空の目が 74件できた）
  - 頭の数字は OCR の番号を使う（「7林業改善…」と読み、番号の印字のない前年度のみの目に番号が付いた）。読みが金額の形（数字だけ）になった行は
    OCR の読みのまま（2行の事項の2行目の1字「費」を「19」と読み、解釈が金額にした）
  - 縦横比を保って右を白で埋める読み方は、目の名前の正解が 20件中 18 → 1件に落ちたので採らない（NDLOCR-Lite は引き伸ばした行で学習している）
  - 書き出しは、NDLOCR-Lite の読み取りの目の並びと金額が今の OCR と同じことを確かめ、違えば止める（OCR を流し直した後の読み直し忘れ・上の崩れに気づく）
- 効果（一般会計。公開データの名前を正解に、目の中の金額で読み取りを対応させて数えた）:

  | 名前 | 件数 | 新 OCR が正しい | NDLOCR-Lite が正しい |
  |---|---|---|---|
  | 細節（画像で確かめて修正表に入れた名前） | 63 | 41 | **63** |
  | 細節（全部） | 2,011 | 1,963 | **2,011** |
  | 説明欄の事項（画像で確かめて修正表に入れた名前） | 134 | 94 | **118** |
  | 説明欄の事項（全部） | 1,076 | 980 | 1,006 |

  画像で確かめる必要のあった名前の多くを NDLOCR-Lite は正しく読む。次の年度のデータや補正予算の画像の回では、
  OCR と NDLOCR-Lite の一致で裏付けが取れ、画像で確かめる名前が減る見込み（8章の2）
- Tesseract（8章の1）: NDLOCR-Lite が誤る事項は、ほとんどが名前の端のごみ（支えにしか使わないので害はない）。細節は全部正しい。
  今は足さなくてよい
