# local-main への最初の PR の前のセルフレビュー計画

状態: 実施中（PR ごとに行う）

## 背景（2026-11-06 の決定）

当初は「画面ができてから PR」としたが、同日に方針を変え、**重ねた作業ブランチを順に local-main へマージする**ことにした
（PR1 計画・抽出と検算・共通 JSON 形式の設計 → PR2 型と検証・書き出し・名前の裏付け・正規化データ → PR3 画面の設計書 → 画面）。
各 PR の前に下の観点でセルフレビューをし、PR では CodeRabbit のレビューを受ける（福岡市版と同じ。スターが10未満の repo は
自動レビューが走らないので、PR に `@coderabbitai review` とコメントして頼む）。PR1 は 2026-11-06 にマージ済み。

```
local-main
  └ docs/local-gov-plan         … 計画・ノウハウ・福岡県の抽出と検算のスクリプト・テスト
     └ docs/local-gov-data-format … 共通 JSON 形式の設計
        └ feat/local-gov-types    … 型と検証
           └ feat/fukuoka-export  … 福岡県の書き出し（正規化データ）
              └ （画面のブランチ）
```

PR は上から順に出し、PR の説明にマージの順番を書く。

## 確かめること

| 観点 | 確かめること | 方法 |
|---|---|---|
| コード | 不具合・取りこぼし・簡潔さ | `/code-review`（local-main との差分全体）。指摘は直すか、直さない理由を PR に書く |
| 設計との一致 | 承認済みの設計書（`tasks/` で状態が「承認済み」のもの）どおりか。設計から変えた点は設計書に反映済みか | 設計書と差分を突き合わせる |
| フォーク元との衝突 | 国版のファイルの変更が差し替え口（ブランド・ナビ・共通部品・`.gitignore` など）に限られているか。国版の表示が変わっていないか | `git diff local-main --stat` で国版のファイルを洗い出す。国版のページを画面で確認 |
| データの正しさ | 全検算・回帰テスト・データの検証テストが通るか | [テストと回帰の運用](../knowhow/テストと回帰の運用.md) の3種類と `npm run lint`・`npm run typecheck` |
| 画面 | 数字・名前・操作（選択・全部の流れ・切り替え）が正しいか | 開発サーバーで目視。スマートフォンの幅も |
| 公開してよい内容か | 原本（PDF）・ローカルの絶対パス・キーを含まない（データ以外のファイルも）。名前が OCR のまま（`name_src: ocr`）の箇所をどう見せるか | **最後のコミットの後に** `git diff local-main...HEAD` で PR 全体の差分を見て、追加行に絶対パス（`/home/`・`/tmp/`）・キーの形（`sk-`・`SERVICE_ROLE_KEY=` など）がないかを grep。PDF・画像・大きいファイルがないか（`git diff --numstat`）。データの grep |
| 文書 | ノウハウ・自治体別の文書・作業報告が最新か | 目視 |
