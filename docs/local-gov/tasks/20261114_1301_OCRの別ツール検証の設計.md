## 1. 目的

今の OCR は2つとも PaddleOCR 系（RapidOCR の PP-OCRv6 日本語と、旧 PP-OCRv4）。多数決の3つ目は文字層。
**同じ系統の2つは同じ字を同じように読み違える**（「両築平野」を2つとも読み違えて readings の裏付けになった。2026-11-14）。
系統の違う OCR を足すと、(1) 読み違いの見つけやすさ、(2) 多数決の強さ が上がるかを確かめる。

## 2. 候補

| 候補 | 系統 | 入れられるか |
|---|---|---|
| **NDLOCR-Lite**（国立国会図書館、CC BY 4.0、2026-11-11 版） | DEIM（配置）＋ PARSeq（文字の認識）。日本語の印刷物・手書きで学習。ONNX・CPU | モデル同梱。依存は pip で入る（flet の GUI は不要） |
| EasyOCR | CRNN（torch） | pip で入るが torch が重い。次点 |
| Tesseract（jpn） | LSTM | apt が要る（sudo なし）ので外す |

まず NDLOCR-Lite を試す。

**動かし方**: NDLOCR-Lite の `ocr.py`（ダウンロードしたコード）は実行しない（権限の確認で止まった。外部のコードをそのまま動かさない）。
同梱の ONNX モデル（データ）と文字表（`config/NDLmoji.yaml`）だけを、自分で書いたスクリプトから onnxruntime で動かす。
使うのは**文字の認識（PARSeq）だけ**。行の切り出しは今の OCR（PP-OCRv6）の文字枠を使う。前処理・後処理は `parseq.py` と同じ
（高さ×幅に縮める、RGB を [-1,1]、出力の各位置の最大の字を 0（終わり）まで。30字・50字・100字のモデルを字数で使い分ける）。
→ 行の位置は同じで、**認識の違いだけ**を比べられる（名前の読み違いの多くは認識の誤り）。

モデル・依存は `~/data/rs-vis-fukuoka/alt-ocr/` に置く（コミットしない）。

## 3. 比べ方

正解の分かる名前・金額で、PP-OCRv6（新）・PP-OCRv4（旧）・NDLOCR-Lite の正解率を比べる。

1. **細節の名前（全件・偏りなし）**: 細節の言い方は 36種類に決まっている（2026-11-14 に全件の名前を確かめた）。公開データの細節の名前を正解とする
2. **説明欄の事項の名前**: 正解は公開データの名前のうち、出典が search・reference・correction のもの（読み取り以外で裏付けのある名前）
3. **今回画像で確かめた読み違い**（細節 22・事項の読み違い）: NDLOCR-Lite が正しく読めたか（補い合えるか）
4. **金額**（細節・事項）: 正解は検算の通った公開データの金額

比べるときは、全角半角・空白・事項の印（○）をそろえる（`name_evidence.normalize` と同じ）。

## 4. 判断の目安

- NDLOCR-Lite の正解率が PP-OCRv6 と同じくらいで、**誤り方が重ならない**（PP-OCRv6 が誤った名前を正しく読む割合が高い）なら、
  多数決の3つ目（または4つ目）として足す価値がある → 組み込み方は報告後に相談
- 金額は今の2つで検算が全部通っているので、金額の改善は目的にしない（誤り方の参考に見るだけ）
