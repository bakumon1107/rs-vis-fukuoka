## 1. 目的と範囲（MVP）

福岡県 R8 当初予算（正規化データ `public/data/local-gov/fukuoka-pref/budget-2026-initial.json`）を、サンキー図で見られる画面を作る。

| 見方 | 列 | 状態 |
|---|---|---|
| **一般会計（既定）** | 財源 → 款 → 項 → 目 → 事項 | MVP |
| 全会計 | 歳入の款 → 会計 → 款 → 項 → 目 | MVP（純計は入れない。総計であることを明示） |
| 決算（R6） | 部局 → 款 → 項 → 目 → 節 | R6 決算の書き出しができてから |
| 補正後 | 当初＋補正（最新） | 補正の取り込みができてから（データの形は対応済み） |

範囲外（MVP の後）: 回ごとの補正の差分、前年比較（R7 の取り込みの後）、議会での言及、1人あたり（人口の出典の確認の後）。

## 2. グラフの作り方: 事前に作るか、画面で組み立てるか

共通 JSON 形式の設計書（5章）は「グラフのファイル（`graph-*.json`）を事前に作ってコミットする」とした。実データができたので見直す。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 事前に作る（当初の設計） | 生成スクリプトで `graph-<年度>-<基準>.json` を作りコミット | 画面は読むだけで軽い。国版と同じ | 正規化データとグラフの二重管理（作り直し忘れで食い違う）。見方（列の組み合わせ）ごとにファイルが増える |
| **B. 画面で組み立てる（提案）** | 画面が正規化データを読み、純粋な関数（`app/lib/local-gov/graph.ts`）でグラフを作る | 正が1つ（正規化データ）で食い違いがない。見方の切り替え・選択時の組み立て直し（3.3）が同じ関数でできる。関数を単体テストできる | 画面の読み込みが大きい（1.2MB。転送時の圧縮で約0.2MB）。組み立ての計算（目 495・事項 約1,100）は軽い |

**B に決定（2026-11-06）。** 地方版のデータは国版よりずっと小さく、二重管理の害の方が大きい。データが大きくなったら（目安 1ファイル 10MB 超）、同じ関数を生成スクリプトから呼んで A に切り替えられる。
→ 共通 JSON 形式の設計書の 5〜7章を「グラフの形（型）は同じ。作るのは画面の側」に改めた。

## 3. グラフの組み立て（`app/lib/local-gov/graph.ts`、純粋な関数）

### 3.1 入力と出力
- 入力: 正規化データ（`LocalBudgetFile`）、見方（列の組み合わせ）、絞り込み（会計・款など）
- 出力: `LocalGraph`（型は共通 JSON 形式の設計書 5章のまま）。ノードは目の行（`row`）に戻れる

### 3.2 帯の作り方（推計を入れない）
- 財源 → 款: その款のすべての目の財源内訳（国庫支出金・地方債・その他・一般財源）の合計。**説明書に印字された数字の合計**で、按分しない
- 款 → 項 → 目: 目の本年度の合計
- 目 → 事項: 説明欄の事項の金額（入れ子の内訳は除き、親の事項だけ）。事項のない目（税交付金・公債費の元金など）は目で止める
- 全会計の見方の 歳入の款 → 会計: 歳入の目の合計。会計 → 歳出の款: 歳出の目の合計。歳入と歳出は会計の箱で合流する（どの歳入がどの歳出に行ったかは資料にないので結ばない）
- 金額は円の整数のまま。各列の合計が同じになること（一般会計の見方: どの列も 2,300,027,028,000 円）をテストで確かめる

### 3.3 選んだときの組み立て直し（按分しない）
国版の絞り込み（`app/lib/sankey-focus.ts` の `focusSankey`）は、祖先側の帯の太さを**割合で按分**する。
財源を左端にすると、ある目を選んだとき、款全体の財源の割合で按分した帯になり、**その目の実際の財源内訳（説明書の数字）と違う太さ**になる。
地方版では、目・項・款を選んだら、**選んだものに含まれる目の財源内訳だけから帯を組み立て直す**（同じ関数に絞り込みを渡す）。

## 4. 画面

### 4.1 ページと置き場所
- `app/local/[gov]/page.tsx`（例 `/local/fukuoka-pref`）。地方版の画面はここに集め、国版の画面のファイルは変えない（全体計画 4.1 の案 B）
- 国版と地方版の切り替え（環境変数・ナビ・トップ）は全体計画のフェーズ2で別に作る。それまでは URL を直接開いて確認する
- 年度・見方・選択は URL のクエリに持つ（国版と同じく共有できる）

### 4.2 部品
| 部品 | 中身 | 国版から |
|---|---|---|
| `client/components/local-gov/LocalSankeyChart.tsx` | 描画（SVG）・選択・ホバー・拡大縮小 | 配置計算 `computeMOFSankeyLayout`・帯の形 `mofRibbonPath` を使う。国版の `UnifiedSankeyChart`（国の列に依存）は使わない |
| `LocalDetailPanel.tsx` | 選んだ目の詳細: 本年度・前年度・増減、財源内訳、節（性質）、説明欄の事項、出典（PDF のページへのリンク）、値・名前の出典の印 | 横のパネルの枠 `SidePanelChrome`・`useSidePanel` を使う |
| `LocalSourcesPage`（`/local/[gov]/about`） | 説明と出典: 検算の方法と結果（`checks`）、修正表で直した値の一覧、資料の一覧（URL・SHA256・取得日） | 新しく作る |

### 4.3 見やすさの要件（事例調査 3・4章）
- 選んでいない流れと箱は**灰色**にする（色を消す）。選んだ経路だけ元の色
- 図の上に「選択中: ○○ ／ **全部の流れを見る**」を常に出す（選択の解除を明示的な操作にする）
- 初めて開いたときに「四角を押すと、その流れだけを表示します」と案内する
- 深い列（目・事項）は、款・項を選んだときだけ開く。最初は 左端 → 款 → 項 まで
- 項目が多い列は上位 N 件＋「その他」にまとめる。選んだ経路の中では、まとめを開いて見せる
- 一般会計だけの見方では会計の箱を置かない（列を増やさない）。全会計の見方では会計の列を置く
- スマートフォンの幅では3列程度にし、押して1段ずつ深くする

### 4.4 確からしさの表示
- 名前の出典が `ocr`（裏付けなし）の箱・事項には印（例「名前は読み取り」）を付ける
- 値の出典が `correction`（画像で確認して修正）・`textlayer`（文字層から採用）の値は、詳細パネルで出典を示す
- 総計（会計間の重複を含む）であることを全会計の見方に明示する（純計は MVP の後）

## 5. テストと確認

- `graph.ts` の単体テスト: 列ごとの合計の一致、財源の帯の合計＝款の財源内訳の合計、選んだときの組み立て直しが目の実際の財源内訳と一致、事項のない目の扱い
- 画面: 開発サーバーで目視（一般会計・全会計、選択・全部の流れ・深い列の開閉、スマートフォンの幅）。数字は詳細パネルと説明書の PDF の同じページを突き合わせる（抜き取りで10目）
- 国版の画面（`/budget-sankey` など）の表示が変わらないこと
- lint・typecheck・`npm test`（Node.js 22）
