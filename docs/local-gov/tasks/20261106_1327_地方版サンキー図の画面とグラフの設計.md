## 2. グラフの作り方: 事前に作るか、画面で組み立てるか

共通 JSON 形式の設計書（5章）は「グラフのファイル（`graph-*.json`）を事前に作ってコミットする」とした。実データができたので見直す。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 事前に作る（当初の設計） | 生成スクリプトで `graph-<年度>-<基準>.json` を作りコミット | 画面は読むだけで軽い。国版と同じ | 正規化データとグラフの二重管理（作り直し忘れで食い違う）。見方（列の組み合わせ）ごとにファイルが増える |
| **B. 画面で組み立てる（決定）** | 画面が正規化データを読み、純粋な関数（`app/lib/local-gov/graph.ts`）でグラフを作る | 正が1つ（正規化データ）で食い違いがない。見方の切り替え・選択時の組み立て直し（3.3）が同じ関数でできる。関数を単体テストできる | 画面の読み込みが大きい（約1.6MB。gzip で約0.1MB。名前の出典を足した後の 2026-11-06 時点）。組み立ての計算（目 495・事項 約1,100）は軽い |

**B に決定（2026-11-06）。** 地方版のデータは国版よりずっと小さく、二重管理の害の方が大きい。データが大きくなったら（目安 1ファイル 10MB 超）、同じ関数を生成スクリプトから呼んで A に切り替えられる。
→ 共通 JSON 形式の設計書の 5〜7章を「グラフの形（型）は同じ。作るのは画面の側」に改めた。

## 3. グラフの組み立て（`app/lib/local-gov/graph.ts`、純粋な関数）

### 3.1 入力と出力
- 入力: 正規化データ（`LocalBudgetFile`）、見方（列の組み合わせ）、絞り込み（会計・款など）
- 出力: `LocalGraph`（型は共通 JSON 形式の設計書 5章のまま）。ノードは目の行（`row`）に戻れる

### 3.2 帯の作り方（推計を入れない）
- 財源 → 款: その款のすべての目の財源内訳（国庫支出金・地方債・その他・一般財源）の合計。**説明書に印字された数字の合計**で、按分しない。
  財源内訳のない歳出の目（R8 は 0件。ほかの自治体・年度の書き出しで起こりうる）は「財源の記載なし」の箱（`funding:none`）から款へ流す
  （目を図から落とさず、財源の列の合計も歳出の総額のまま）。この箱を選んだときもほかの財源と同じく、その目の本年度で目まで追う
- 款 → 項 → 目: 目の本年度の合計
- 目 → 事項: 説明欄の事項の金額（入れ子の内訳は除き、親の事項だけ）。事項のない目（R8 の一般会計の金額のある目で 水防費・直轄河川災害復旧負担金・
  庁舎等災害復旧費・予備費の4つ）は目で止める。税交付金・公債費の元金などは事項が1つで金額の記載がなく、目の額を当てた事項として帯を出す（4.4）
- 全会計の見方の 歳入の款 → 会計: 歳入の目の合計。会計 → 歳出の款: 歳出の目の合計。歳入と歳出は会計の箱で合流する（どの歳入がどの歳出に行ったかは資料にないので結ばない）
- 箱の ID: 款・項・目は**会計・歳入出・番号**で決める（款の番号は会計ごと・歳入出ごとに付くので、番号だけでは別の会計の款が混ざる。
  名前だけでも、特別会計の公債費・総務費が一般会計の箱に混ざる）。全会計の見方の**歳入の款は名前でまとめる**（繰入金・諸収入・県債などは
  複数の会計に出る。「どの財源から各会計にいくら」を見る列なので、同じ名前の歳入は1つの箱から各会計へ帯を出す）。
  名前でまとめた箱の印は、まとめた行の印を足し合わせる（まとめた行のどれかの名前が読み取りのみなら、箱にも「名前は読み取り」の印。4.4）
  - 事項の箱は**目の行の ID ＋ 正規化データの事項の番号**（`item:<目の行の ID>:<番号>`。例 `item:general/expense/1-1-1:0`。
    目の箱の ID `moku:<目の行の ID>` の `moku:` は付けない。番号は `items` の配列の位置で、入れ子の内訳も数える。
    親の事項の番号は飛ぶことがある。データを書き出し直して事項の数が変わると、共有した URL の選択が別の事項を指すか、外れる（図にない番号なら選択なしに戻る）。
    事項の名前で決め直すのは、同じ目に同じ名前の事項があり得るので MVP ではしない。補正後への切り替えを足すときは、補正で足された事項・
    名前でまとめた事項で当初と補正後の番号がずれうるので、そのときに事項の ID の決め方を見直す）。名前では決めない（R8 の一般会計で「職員費」は 52 の目、
    「運営費」は 14 の目に出る。名前でまとめると別の目の事項が1つの箱に混ざり、選択の URL もあいまいになる）
  - 上位 N 件以外をまとめた箱は `other:<列>`（4.3）。名前（「その他」）では決めず、事項の名前（「その他経費」など）と ID が重ならない形にする
- 箱のラベル: 全会計の見方で、同じ名前の歳出の款が複数の会計にあるときは、会計の名前を添える（R8: 公債費 4・予備費 3・総務費 2・積立金 2。
  添えないと同じラベルの箱が並び、どの会計か分からない）
- 金額が 0 円の目（本年度の計上がない目。R8 で10件: 知事選挙費・参議院議員通常選挙費などの選挙費6件と歳入4件。どれも前年度は計上あり）は
  箱も帯も作らない（高さ 0 の箱と重なるラベルを避ける）。かわりに「データについて」に一覧（会計・歳入出・款・項・目・本年度と前年度の額と値の出典の印）を出す
- 図にない箱を指す選択（書き出し直しで事項の番号が変わった URL・別の見方の ID など）は、選択なしに戻す（深い列も開かない）
- 本年度が読めない目（`amount.v` が null。R8 は 0件）も 0 円の目と同じく箱を作らず、「データについて」の一覧に「本年度 読めない」と出す
  （計上がない目と見分ける。全検算が通らないので `checks.all_ok` も減り、データの一覧の `status` は verified にできない）
- 金額が読めない事項（`amount.v` が null）は箱も帯も作らない（R8 は 0件。あると、その目の事項の合計が目の額より小さくなり、
  事項の列の合計も 3.2 の値からずれるので、テストで気づく）
- **0 円の帯は作らない**（財源 → 款 で、その款のどの目にもその財源がないとき。R8 の一般会計で9本: 議会費・公債費・諸支出金・予備費への
  国庫支出金など。財源を選んで目まで組み立て直すときも、その財源が 0 円の目への帯は作らない）
- 金額は円の整数のまま。財源・款・項・目のどの列も合計が同じになること（一般会計の見方: 2,300,027,028,000 円）をテストで確かめる。
  事項の列は、事項のない目の分だけ小さい（R8 の一般会計で 328,571,000 円。目で止まる）。かわりに、**入りと出の両方がある箱**で入りと出の帯の合計が
  等しいこと（事項のある目では 事項の合計 = 目の額）を確かめる。端の箱は別の条件で確かめる: 左端（一般会計の財源）は出の合計 = その財源の内訳の合計（「財源の記載なし」は財源内訳のない目の本年度の合計）、
  左端（全会計の歳入の款）は箱の値 = 同じ名前の歳入の款の目の本年度の合計（公営企業会計を除く全会計をまたいで。箱の割り振りの誤りに気づく）。
  あわせて、名前の空白・全角半角の違いを除くと同じになる箱が2つないこと（表記ゆれで同じ款が2つの箱に割れていないこと）を確かめる。
  右端（事項・事項のない目）は箱の値を正規化データの額（事項の金額・目の本年度）と比べる（箱の値は入りの帯の合計から決まるので、
  入りと比べても誤りに気づけない）。帯の値はすべて正（サンキー図は負の太さを描けない）
- 全会計の見方の会計の箱は、入り（歳入）と出（歳出）が等しい前提（一般会計・特別会計は歳入 = 歳出。R8 で全会計を確認）。
  **公営企業会計は対象外**: 収益的収支と資本的収支に分かれ、資本的収支の不足を補填財源で埋めるので、歳入と歳出が一致しない。
  全会計の見方は、正規化データに公営企業会計（`kind: 'enterprise'`）があっても描かず、画面に「公営企業会計は含みません」と出す。
  公営企業会計の見方（別の見方にするか、差を「補填財源」の箱で示すか）とテストの条件は、公営企業会計を書き出すときに決める

### 3.3 選んだときの組み立て直し（按分しない）
国版の絞り込み（`app/lib/sankey-focus.ts` の `focusSankey`）は、祖先側の帯の太さを**割合で按分**する。
財源を左端にすると、ある目を選んだとき、款全体の財源の割合で按分した帯になり、**その目の実際の財源内訳（説明書の数字）と違う太さ**になる。
地方版では、目・項・款を選んだら、**選んだものに含まれる目の財源内訳だけから帯を組み立て直す**（同じ関数に絞り込みを渡す）。

画面ではこの組み立て直したグラフを**単独では出さない**。全体のグラフ（左の列）を灰色で敷いたまま、組み立て直したグラフの帯の値を
元の色で重ねる（4.3 の「選んでいない流れは灰色」）。帯の一部だけが選んだものに当たるとき（目を選んだときの 財源 → 款）は、
組み立て直したグラフの値の割合の太さで重ねる。深い列（最初の3列より右の列）は、組み立て直したグラフに出てくる箱と帯だけを足す（`graph-view.ts`）。
深い列の箱と帯は全体の額（目の本年度・事項の金額）で描き、選んだものの分は重ねる帯で示す（財源を選んだときも、目の箱は目の額。
財源の額で描くと、箱の金額が詳細パネルの本年度と合わず、目の額に見えてしまう）

選ぶものごとの扱い（資料にある数字だけで重ね、資料にない対応は色を付けない。2026-11-07 PR3 の CodeRabbit の指摘で追記）:

| 選ぶもの | 重ねる帯 | 色を付けないもの（灰色のまま） |
|---|---|---|
| 款・項・目（一般会計） | 選んだものに含まれる目の、財源内訳・本年度の金額。開いた列の分だけ（款は目まで、項・目は事項まで開くので、事項の金額は項・目を選んだときだけ。4.3） | — |
| **財源**（一般会計） | 各目の財源内訳のうち選んだ財源の額で、財源 → 款 → 項 → 目 を組み立て直す（財源内訳は目ごとに印字されているので按分なしで目まで追える）。目まで開き、事項の列は開かない（財源内訳は目の単位で、事項ごとの内訳は資料にない）。「財源の記載なし」を選んだときは、財源内訳のない目の本年度で同じように目まで | — |
| **事項**（一般会計） | 款 → 項 → 目 → 事項 の帯に、その事項の金額（事項は目に含まれ、目は項・款に含まれるので按分にならない）。事項の列には同じ目の事項を並べ、選んだ事項だけに色を付ける（ほかの事項は灰色） | 財源 → 款（事項ごとの財源内訳は資料にない。目の財源を重ねると、事項の財源として過大に見える）。図の上に「事項ごとの財源は資料にないため、財源の帯は色を付けていません」と出す |
| 会計（全会計） | その会計の歳入の目（歳入の款 → 会計）と歳出の目（会計 → 款 → 項） | — |
| **歳出の款・項・目**（全会計） | 会計 → 款 → 項 → 目 の、選んだものの分 | 歳入の款 → 会計（どの歳入がどの歳出に使われたかは資料にない）。図の上に「歳入のどれが使われたかは資料にないため、歳入の列は色を付けていません」と出す |
| 歳入の款（全会計） | その款から各会計への帯 | 会計から先（どの歳出に使われたかは資料にない）。図の上に「どの歳出に使われたかは資料にないため、会計から先は色を付けていません」と出す |

### 4.3 見やすさの要件（事例調査 3・4章）
- 選んでいない流れと箱は**灰色**にする（色を消す）。選んだ経路だけ元の色
- 選んでいるあいだは、図の上に「選択中: ○○ ／ **全部の流れを見る**」を常に出す（選択の解除を明示的な操作にする）
- 何も選んでいないときは、図の上に「四角を押すと、その流れだけを表示します」と、見方ごとの開き方を案内する（初めてかどうかは区別しない。選択を外したときにも出る）
- 最初は左の3列だけを出す（一般会計: 財源 → 款 → 項、全会計: 歳入の款 → 会計 → 款）。深い列は箱を選んだときだけ、選んだものの分を開く:
  - 一般会計: 財源・款を選ぶと目まで（事項まで開くと、R8 の一般会計で農林水産業費 178件・教育費 160件・総務費 158件になる。財源は事項の内訳が資料にない）。項・目・事項を選ぶと事項まで
  - 全会計: 会計を選ぶと項まで。款・項・目を選ぶと目まで
  - 全会計の歳入の款は絞り込まない（どの歳出に使われたかは資料にない）。その箱から出る帯だけを元の色で重ねる
  - 重ねる帯と色を付けないものは 3.3 の表のとおり
- 深い列（最初の3列より右の列。一般会計では目・事項、全会計では項・目）の右端で箱が多いときは、金額の上位 N 件＋「その他」にまとめる
  （重ねる帯も足し合わせる）。選んだ箱はまとめに入れない。
  上位を選ぶ金額は**重ねる帯の額**（選んだものの分。財源を選んだときはその財源の額）で、同じなら箱の額。箱の額で選ぶと、
  選んだ財源が多く入っている目が「その他」に入ってしまう。
  「その他」の箱は選べない（中身はほかの箱を選び直して見る。URL で `other:` を指定しても選択なしになる）
  N = 25（`graph-view.ts` の `TOP_N`）。右端の箱が N + 1 件以下、またはまとめる箱が1件以下ならまとめない（「その他 1件」は作らない）。
  最初の3列の右端（一般会計の項 62件・全会計の款 43件）は、選んで先を開く入口なのでまとめない（多すぎるかは画面を見て決める）
- 一般会計だけの見方では会計の箱を置かない（列を増やさない）。全会計の見方では会計の列を置く
- スマートフォンの幅では3列程度にし、押して1段ずつ深くする（**未実装。画面を見て決める**。2026-11-07 時点の試作は、図の幅を最小 640px に
  固定して枠の中で横にスクロールする。詳細パネルは国版と同じく画面の下から出し、本文の幅は狭めない）

### 4.4 確からしさの表示
- 名前の出典が `ocr`（裏付けなし）の箱・事項には印（例「名前は読み取り」）を付ける。名前の出典がない名前（`name_src` は省略できる）も
  裏付けがないので `ocr` と同じに扱う（図の印・詳細パネル・「データについて」の件数のどれでも）。複数の行を名前でまとめた箱
  （全会計の歳入の款）は、まとめた行のどれかが読み取りのみなら印を付ける（裏付けのない名前を裏付けありに見せない）。名前の出典の内訳（`correction` 画像で確認 など）は
  「データについて」で件数を示す
- 値の出典が `correction`（画像で確認して修正）・`textlayer`（文字層から採用）・`blank-as-zero`（空欄を 0 とみなした。推定に近いので
  確定した値と見分けがつくように）・`inferred`（推定）の値は、詳細パネルで出典を示す。図に箱を出さない 0 円の目（3.2）の本年度・前年度は、
  「データについて」の一覧で同じ印を付ける（R8 の `blank-as-zero` の本年度 10件は、すべてこの一覧の目）。
  図からも詳細パネルからも見られない値（歳入の目の値。R8 で前年度が `blank-as-zero` の歳入の目が5件）もあるので、「データについて」に
  **確定した読み取り（`ocr`・`text`）以外の出典の値をすべて**一覧で出す（目・値の種類・出典）
- 箱の印（名前は読み取り など）は、図に出る行（0 円でない行。財源で絞ったときはその財源が 0 円でない行）だけから決める。
  名前でまとめる箱（全会計の歳入の款）に、図に出ない行の印を混ぜない
- 説明欄に事項が1つで金額が印字されていない事項（`no_amount_printed`。目の額を当てた）は、詳細パネルで「金額の記載なし（目の額）」と示す
- 総計（会計間の重複を含む）であることを全会計の見方に明示する（純計は MVP の後）
